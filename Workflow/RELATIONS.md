# Workflow - relations to the other projects

A hypothesis ledger, as in the other projects. Each entry is a claim, its status in the record's own terms (**stated**, **seen**, **open**), where the evidence is, and what is still open. A claim lives in the project that makes it; entries are added, updated or marked rejected, never removed. This project also writes here what it asks of the other projects; the asks are made there, under those projects' own plans, never from here.

---

## W-R1. The semantics is the authority, and only file 10
**Claim.** Every term the programme uses is file 10's, quoted at the sentence; where the programme builds an object the theory permits but does not contain, it says so. File 20 is set aside (Semantics decision S4) and nothing rests on it.
**Current status.** Seen on the plan itself: a judge checked draft W1 sentence by sentence against file 10 (log W2) and found nine passages read wider than written or cited to the wrong Part, all corrected in W3; every quotation in W3 is checked by program for presence and Part (`rigs/W3 quote check/`). Two attack points of the theory are named where the plan rests on them ((D) under M2, (B) under M8a).
**Open question.** Which of the owner's six unknowns the theory as written cannot reach (W3 prediction P1.2). Already recorded as not reached by this programme: the attention half of Q1 and the generation half of Q5. An unknown the theory cannot reach is written here as an ask for the owner, never as a change to the theory.

## W-R2. The HV Skill is the judge the workflow calls, and the model places it
**Claim.** The skill carries the theory's Account check (Part V) and support tests (Part VI) for an agent at one call; the model of phase 1 says which of its tests need a target carried across calls (the same-explanation verdict, pairs that pull, the best rival) and which do not. The skill is frozen (file 33) and is not changed by this project.
**What this project asks of the HV Skill, when phase 1 freezes the model's word list:** one change to the skill's word list under that project's own plan, in two items: the nine loose rows of its H69, and the eleven unmapped notions, of which the second (obligations held fixed for the comparison, which gives *fixed* its reading) and the fourth (the finite monotone theorem's condition) are the ones this plan's model needs. Not before phase 1. **And of the owner:** the words after decision H7 that cap a judging round at five ("There is no need for 20 different agents. 5 tops") are recorded in HV log H69 and its INDEX and in no Decisions file; they are asked to be entered there.
**Current status.** Stated (plan W3, section 12). The record judge of W2 found the draft's ask read as three items where it is two (log W2). The boundary between the skill and the planning work is HV RELATIONS R6, read only.

## W-R3. The Planning skill's loop is every phase's loop
**Claim.** Each phase of the programme is a numbered plan frozen with predictions as counts that could fail, run on the owner's word, read under frozen criteria, with a results file that names what it did not test (Planning file 2). The plan W1 is itself written to that skill.
**What this project asks of Planning, after phase 4 of W3:** whether an agent's arrangement (stateful, stateless, what it is handed at each call) belongs in `readers-and-markers.md` or in the workflow's arrangement; and the sorting of marked fields into within-step and cross-step, if prediction P4.2 holds.
**Current status.** Stated.

## W-R4. The Language project's checker is the one rule-signature component in the repository
**Claim.** A component whose relation is "invariant under interventions on the world and variable under edits to the rule" (file 10, Part II) is what the theory calls a rule application; the Language project's checker (fixed rules on s(CASP), marked *Borrowed* in its own L64) is the only component in the repository with that signature that reads a text's reasoning, and is the workflow's candidate for that place; the HV rigs' marking programs have the signature too and read reports, not reasoning. L64 is a draft awaiting the owner's strikes and nothing here rests on it as settled.
**Current status.** Stated (plan W3, section 6), narrowed by two W2 judges from the draft's wider claim. Read only; nothing asked of Language.
**Candidate, held.** The rival judge of W2 named L64's own variation test (change the prose, translate again, the ledger changes as the commitments do and nowhere else) as a marker-free read-out phase 4 could use; it trespasses on that project's open job ("Not tested: a translator other than Claude") and needs the path fix its README names, so it is held here as an ask if a phase plan wants it, and nothing is written there.

- That any agent belongs to the theory's classes. File 10: "It does not prove that any human, machine, institution, or lineage belongs to the classes defined. It defines the classes."
