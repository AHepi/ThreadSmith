# A Language-Model Agent in the Semantics of File 11

## A standalone theory of what an agent built on a large language model instantiates of the semantics, at one call, across calls, only with a record or a harness, and never

*W9, 22 September 2026. A restatement of model W8 (the Workflow project's first authority, built by three Opus 5 builders and judged by two under plan W6) as a theory in the shape of Semantics file 11: the same claims, the same holders, the same standing, reordered into primitives, indices, definitions, constructions, derivations and what defeats it. It adds no claim W8 does not carry, and it carries W8's standing on every claim (section XIV). Where W8 says a part is held if, unknown, or a construction, this theory says so. It has not been judged as a theory; W8 has, and this is a reading of it. Nothing here is a test: no reader has run under it.*

---

# Part 0 — Read this first

## What this theory claims

An agent built on a large language model is, at one call, an execution of a task in the physical module's sense: a fixed set of passages read, a set of passages written. What the text of a call instantiates is an organization at the grain of text, adopted as a coarse physics, whose input ports are the passages an admitted edit sets and whose output ports are the passages a component determines. One organization at one pair may have several compatible valuations, so two calls on one context may differ, and every claim about a difference between arrangements is read only beyond that spread.

The weights instantiate an organization that admits a transport with selected provenance, whose population is the set of transports the physics and the architecture admit. Under the qualified Derivation 3, at a pair the training history never met, the history settles nothing and the population may fix the value. Whether the last clause of a selected provenance holds for a model trained on text about training is unknown; if it fails, the provenance is declared, and a declared transport makes no occurrence represent anything.

A skill file in the context is a carrier. Whether a reader represents its content is a fidelity fact with a history, and this theory attributes it to no reader. Copying the method's form is relay, and relay is not construction.

Stateful and stateless name a construction on retention: a stateful agent is one whose constructor attribute between calls carries the represented targets of unfinished work, a stateless agent one whose attribute is only what its carrier text carries. The difference tracks what is represented at each call, not the label. What a call's context must carry is the frozen question, its change list and the parts under test; a target may also come from the weights, with fitted provenance. External memory is occurrences outside the context brought in by a transport with a provenance; a record derived from a carrier is not a second witness to it; a section of a carrier filled from another source keeps that source's history.

A harness costs two different things, and they fall apart. Setting a port the organization's components assign replaces the component, and the other ports of its footprint lose the relation it imposed. Partitioning a task across calls loses what no call's context holds together. A harness that only adds to what the model reads replaces nothing. "Latent capability" is the theory's owned capability, and a reported difficulty is no barrier.

A policy about what to read is an aspect of practice the semantics names. It is scrutinizable only where a description of it becomes a represented target in the sense of (R), so text in the context is not enough. Under the declared boundary, the reading of a router table at a call is the reader's own and its authorship is not. A trace is a read-out of a route only where the transport records the calls it served; a reader's own list of what it opened is an emission.

Of the twenty-one operations of file 11's dependence order, at most one is placed by continuity alone. The line a workflow must draw between its skills is between what a call carries and what only a record or a program carries, and not chiefly between a stateful and a stateless agent.

## What this theory does not claim

It does not claim that any agent belongs to any class file 11 defines. It attributes creativity, newness, origin and created explanatory knowledge to no agent: (N), (G) and (EK) need a prior repertoire no arrangement at the grain of text supplies, and that placement is not a barrier claim. It attributes deployment to no agent. It attributes representation of the skill's method to no reader, because the record's evidence runs both ways and was written with the skill in view. It says nothing at the grain of weights or activations: that grain is outside the theory by declared scope, and a claim there could contradict this theory without the theory noticing.

It does not say what any agent does. It says which of the semantics' objects an arrangement of an agent can instantiate, and which it cannot at this grain, and what run would catch each claim out.

## What is primitive, what is an index, what is adopted, and what is derived

The primitives are file 11's: the physical module \(\Theta\) and the normative relation \(\mathcal N\). This theory adopts, for the physical module, a coarse physics of text (Part II); the adoption is a fallible physical claim, permitted by the semantics' substrate commitment and open to criticism, and not one of file 11's declared inputs. The indices are file 11's four, declared before any attribution: grain (text), boundary (the reader and the program that hands it its context), continuity (what persists between executions, declared per arrangement) and the contract (the change list of the question in hand). Everything else is derived from file 11's definitions, or is a construction the semantics permits and does not contain, marked as such where it stands.

## Where to attack this

In the order of how much falls if each fails: (A) the placement rule's first rider (Part XII), which carries eight of the twenty-one placements and is held if; (B) the fourth clause of a selected provenance (Part IV), which is unknown and, if it fails, takes representation with it; (C) the reading of the constructor attribute between calls (Part VII), on which the count of operations placed by continuity turns; (D) the two-loss account of a harness (Part IX), whose emission half no run has tested; (E) the adopted physics of text itself (Part II). Part XIII states each with what would refute it.

# Part I — Commitments

The theory takes file 11's six commitments whole: explanatory realism, fallibility without falsehood-as-work, conjecture and criticism, recursive scrutiny with operative return, substrate independence with physical obligations, two provenances. Two bear on every part below. A system can be wrong about its own capacities, so nothing about an agent is read off the agent's account of itself. And every attribution of an organization to a physical system must be permitted by the adopted physics, so the physics of text in Part II is what every attribution here answers to.

# Part II — The call, and the organization at the grain of text

## A call is one execution

One request to the language model is one execution: the smallest unit at which what is read is a fixed set of passages. The context is the occurrences that execution reads; the emission is the occurrences it writes. An agent turn with tool calls, and a session, are several executions, because each re-posts a changed context. "Across calls" means across requests. *Construction, from file 11's task and occurrence sentences (Parts XII, IV); file 11 contains neither "call" nor "context window". Held jointly with the declared grain; the unit moves at another grain, and that is a new index, not a refutation.*

## The adopted physics of text

The organization a call's carrier text instantiates has as its input ports the passages of the context an admitted edit sets, as its output ports the passages of the emission a component determines, as its components the dependences between those passages, and as its admitted edits: change a passage, withhold one, add one. A passage of the context no edit sets, and a passage of the emission no component determines, is not a port of the account. This follows file 11's roles-are-derived paragraph and its rule that a dimension mentioned in passing is not a port until the account admits changes to it. What is held is the tie between the port set and the edit set; the particular edit list is loose and any list an arrangement can actually run could replace it. *Construction; held.*

## Passages the caller did not write

Some passages in the context are written by the serving stack and not by the caller: system-prompt insertions, updates after tool calls, server-side summaries of earlier context. They are in the context and so in the boundary conditions \(B\); they are not input ports of this contract, because no admitted edit of it sets them. They vary with the arrangement, because what they report varies with what the arrangement has accumulated. *Held if the claimed sources describing the serving stack are right; a phase that records the request as sent settles it.*

## One pair, several valuations

A call realizes one edit–boundary pair of the organization and exhibits one of its compatible valuations, and the valuations at one pair may be several: "Several solutions remain several." So two calls on one context may emit differently, which is why every comparison between arrangements carries a run-to-run baseline. A kind, being a signature over a whole contract, cannot be exhibited at one call on a contract with more than one pair; reading a kind off one report is reading a label. *Held, by file 11's sentence and by the record's disagreement between two runs of one box.*

# Part III — What a run settles

Nothing about what an agent instantiates is read off its emission at a fixed input: "The same holds for attribution from emitted text and for use inferred from delivery logs" (Derivation 9). Where two arrangements emit differently under the same inputs, beyond the run-to-run spread of Part II, the contract contains a change that separates them, so they are not one account at this grain; this does not show they are different organizations, since one organization at one pair may have several valuations. Where they agree, the report is that the contract does not contain the distinction (Derivation 2's consequence), and never that they are one organization or that either instantiates anything. Derivation 2's claim itself is about two explanatory candidates satisfying (F1), (F2) and (A), which two arrangements of one reader are not; the agreement is held by the consequence alone. A report written in the skill's words is a carrier that carries the same words, and carrying them settles nothing. *Held; a theorem of file 11 applied.*

A certified field of a marking instrument identifies an arrangement difference; it does not say the field produces it (file 11, Part III, on the identification question against the production question).

# Part IV — The weights, their transport, and its provenance

## The selected transport and its population

The organization the weights instantiate admits a transport with selected provenance on the first three clauses of file 11's definition: a population \(\mathcal T\), which is the set of transports the physics and the stated construction admit, for a language model the architecture and training recipe as stated; a variation operator, the training update; a survival condition, fidelity on a finite history \(H\) of edit–boundary pairs actually encountered, where a pair is one setting of the context ports with its target continuation, not a document. The population is part of the claim. *Construction, from Part IV's definition and Part XII's population sentences; held if the fourth clause holds and if the independence premise of Derivation 3's proof is read as file 11 reads it.*

What follows is the qualified Derivation 3: at a pair outside \(H\), the value is underdetermined by the history wherever the population admits a differing survivor there, and fixed by the population where it does not. For a parametric family whose relations at every pair are computed from one parameter set, the second limb is the live one; whether such a family is a population with no differing survivor at a given pair is not settled here. So this theory never says a reader is unconstrained off its history; it says the history settles nothing there and the population may. The unqualified form, "held only where it was tested", is not used anywhere in it.

## The fourth clause, unknown

File 11's definition ends with a clause this theory cannot settle: no member of the history represents the transport, the history, or the survival condition. A corpus drawn from academic and professional sources contains texts that state loss functions, and a training recipe whose human oversight is a written list of principles puts that list in text. Two readings of the clause are open, the strict one on which members of \(H\) are formal pairs and representation is undefined on them, and the physical one, which Part XII's "a claim about a physical history" favours, on which the clause reaches the occurrences that realised the pairs. On the physical reading the check is a trainer's record, not a run this repository can make. If the clause fails, the provenance is neither selected nor constructed, so by the trichotomy it is declared, and "A declared transport does not make an occurrence represent anything; it makes a modeller assert that it does." Every claim of representation downstream falls with it. *Unknown, with the test named.*

## Provenances are told apart by history

The three provenances are told apart by their histories, not their outputs. So a target a reader names that is in neither the document nor any file it read has a carrier, the weights, and its provenance is fitted: settled by its history only where it was met, and by the population where the population fixes it.

# Part V — Carriers, skills, and representation

## A skill file is a carrier

A skill file in the context is an occurrence. Whether a reader represents the method it carries is settled by (R): the organization the carrier text instantiates must admit a transport to that content, faithful on the content's contract, with selected or constructed provenance. The record holds one version change made as two edits, under which the emission responded at several pairs as the method says and, at two pairs, in ways the method does not license; fidelity does not hold across the whole contract for those readers, and the evidence was written with the skill in view, so it is fitting and cannot confirm. (R) also needs the skill's method written as an organization in Part II's sense before it can be stated of any reader, and that has not been done. This theory therefore attributes representation to no reader. *Held if the method is given an organization and the edited-clause test is run; provenance fitted.*

## Relay is not construction

A call that emits the method's headings, marks and test names has relayed the received content: "Reconstruction by a learner is construction; relay is not." A count of reports in the method's form is evidence about a carrier and bears on no building episode. What would bear on construction is a small binding newly prepared inside received content, with a witness naming the controlled processes, the incoming carriers and the binding; no arrangement in the record supplies one. *Held.*

## The two layers at the grain of text

File 11's primitive layer has a counterpart at the grain of text: an organization whose ports are the items a document keeps identity as through rewording and displacement (a claim, a part, a speaker, a quotation), whose components are their continuity relations, and whose admitted edits are the textual counterparts of displacement (move a passage), occlusion (withhold one) and re-identification (exchange two labels). The simulation layer's counterpart is the organization whose queries are predictions about what such an item takes under an admitted edit, which is what the skill's poke asks for. Whether any reader instantiates either layer is unknown at this grain; the record shows the emission failing at re-identification three times, and the exchange edit is the one no arrangement yet runs. *Construction; unknown, with the test named.*

# Part VI — Boundary and continuity, declared

Before any claim about what an agent owns, retains or loses, two indices are declared and not discovered, as file 11 requires: "Both are declared before the attribution, not chosen after it." The boundary: the system is the reader together with the program that builds and hands it its context; the record, the corpus and the owner are outside it; the skill's text once in the context is inside, and the work of writing it is outside. The continuity: what persists from one execution to the next, which differs by arrangement (a process and its transcript; the carrier text a program hands over; the document and the frozen question alone). That a boundary and a continuity must be declared is held by Parts XII and XIV. Which boundary and which continuity is a free choice that could have been otherwise, and is loose; a line putting the transport program outside, or the record inside, would move the harness and policy claims of Parts IX and X. A verdict that depends on a declared input is a verdict given the input, and where the input is missing the verdict is unsettled. *The requirement held; the particular line loose. Standing: unknown under W6.9.*

# Part VII — Retention, and the arrangement: stateful and stateless

## The construction

A stateful agent is one whose constructor attribute between calls (an attribute being a set of the substrate's states) is the set of states carrying the represented targets of its unfinished work. A stateless agent's attribute between calls is only what its carrier text carries. File 11 has attributes, retained realization (CT1), the retention fixed point (CT2), owned capability and the represented target of a constructed transport, and contains neither word. The pair is not defined by the capability predicted from it: each arrangement's attribute is fixed by what is handed over (a process, a transcript, a summary, a note), which is what file 11's grounding of ownership in the boundary's processes and never in the attributed capability requires, and what its well-founded dependence order requires. The stateful limb names a represented target, and "represented" is (R), so that limb names what would have to be shown. *Construction; held if the arrangement predictions fire on certified fields, and held if Part V's representation claim and Part IV's fourth clause.*

## What the difference tracks

Two arrangements whose calls are handed the same text stand or fall together at this grain: if the carrier carries everything the process carried, no admitted change on the contract separates them, and the report is that the contract does not contain the distinction. So the difference tracks what is represented at each call, not the label, and a framework's "stateful" agent with a checkpointer is, on this theory, a stateless call plus a carrier. What would show this wrong: a fresh call handed the whole transcript disagreeing with the continuing process on a certified field beyond the run-to-run baseline; the candidate reason, named before any run, is thinking a transport keeps or strips between turns. *Standing: unknown under W6.9 on the mark; the counts are unchanged.*

## Within-step and cross-step fields

Fields whose work is done inside one step (a part's mark reached by remove, swap and poke) need only that step's material in the call's context. Fields whose object is the set of parts or the whole candidate (pairs that pull, the best rival, the same-explanation verdict, remove in groups) need a context that holds the parts together, since "the supports assessed are the ones actually written, not a support someone could write in their place". The sorting is about what one call's context holds, not about whether a process persisted, and it is written before any run and never re-sorted on the reports that break it. *Construction, from Part VI and the skill's list of tests; held if the arrangement predictions fire.*

# Part VIII — The context, external memory, and carriers

## What the context must carry

At each call the context must carry the frozen question (its target, its change list, what is asked) and the parts under test. This is a requirement of the practice, not of file 11, which says what a question is and what is prohibited during an assessment and nothing about what an execution must read. The record holds the failure the requirement exists to catch: under identical framing, two of twelve runs froze a different question. *Construction; held if the added requirement is real, and by the arm that withholds the change list.*

## A target may come from the weights

A call can name a target that is in neither the document nor any file it read; its carrier is then the weights and its provenance fitted (Part IV). A rival built from the problem in the context is "a first representation ... constructed from an available problem without prior observation of what it represents", and its target has a carrier. The theory predicts no target with no carrier at all; one falsifies it. *Held if Part IV.*

## External memory

External memory is a set of occurrences that sit outside the call's context and are brought in by a transport. The transport's provenance is declared when the designer wrote the lookup and constructed when the agent built the query from a difficulty it represents. It bears on attention by deciding which targets are represented at the next call. Saying a store is the agent's memory does not make its contents represented. *Construction on Part IV's provenances and Part IX's active route; held if the constructed-query limb does work, which one count tests.*

## A derived record is not a second witness

A wrapped run record, a summary of a return, or a results-file entry derived from a reply is not independent evidence about the call that produced the reply: "a later record derived from the carrier is not a second, independent witness to its history" and "A record reconstructed from the claim it is meant to support is not a receipt for that claim." A carry-over note written by one call and handed to the next is a section of the new call's carrier filled from another source, and keeps that source's history whatever it happens to match; so a fresh call with a note is not the continuing agent with a shorter transcript. Both sentences are file 11's alone. *Held if the added job that results cite receipts is real; the note claim held if the carry-over arm fires.*

# Part IX — Harnesses: the two losses

## Setting a port replaces the component

A harness that writes tokens into the emission, or fixes its shape (a prefilled report skeleton, a closed list the marks must come from), sets ports the organization's own components assign. "An edit that sets a port replaces the component assigning that port; it does not add an equation beside an incompatible one." The set port takes the harness's value; the other ports in the replaced component's footprint lose the relation it imposed, since "A deleted component imposes the full relation on its ports", which is no constraint at all. That loss is what the harness costs. A harness that only adds passages to the context sets no such port and, on this theory, costs no within-step field: it is the bypass. The record has the near case: naming the closed list in the prompt without prefilling did not set the port, and readers wrote marks outside it. *Unknown until the port-setting arm runs; nothing in the record has set an emission port.*

## "Latent capability", and no barrier

What is destroyed, in the semantics' terms, is owned capability on the tasks the unconstrained organization could carry, under the same boundary, continuity and resource contract; it is grounded in the processes the boundary includes and never in the capability attributed. A reported difficulty is a difficulty, not a recorded failure, and "A finite list of failures is not a barrier proof; a bypass refutes a proposed barrier." The attention half of the question has no port at the grain of text and is borrowed from the physical module; its best rival is an account at the grain of activations, which this theory puts outside itself by scope. *Borrowed for the attention half; held for the capability half by Parts XII and XIII.*

## Partition loses what no call's context holds together

When a task is split across calls so that no call's context holds the whole candidate, the results whose object is the set of commitments fall while the results a call can reach from what it holds stand. The ground is Part VI, not (F2): "A block may be critical while no singleton in it is"; a subset's success does not imply the whole's; the supports assessed are the ones actually written. A final call handed a pile of answers assesses no support any call wrote. The record shows the cross-step results reached inside single calls that held the whole document, so the loss is a loss of what one call holds together, not of persistence across calls; and a partition that splits the tests but hands every call the whole document tests nothing here. *Held if the partition arm, splitting the parts, fires.*

# Part X — Practice: policies, scrutiny, and traces

## A policy about what to read is an aspect of practice

File 11 names, among the aspects of a system's practice that can become a target, "a question, a contract, a transport, a method, an attention policy". A skill's router table is such an aspect. The particular word is loose against "a method"; what is held is that the list is open over aspects of practice and names both. Its rival, that a policy is a component of the transport, is right of a limit fixed in a program the reader cannot read and wrong of a table the reader reads, and the record has both. *Held.*

## "Represented" is (R)

Part XIII requires that a description of the aspect become a represented target. File 11 has one predicate meaning represents, (R), and says so in its dependence order; there is no second predicate (the formalism "representing" a phenomenon is a metalinguistic use). So a policy carried as text in the context is not thereby a represented target: the test is whether the reader's reports respond to edits of the policy's words as the policy says they should. Being asked about the policy and answering is an emission, and Derivation 9 bounds it. *Held.*

## Ownership of the routing, and of the table

Under the declared boundary, file 11's ownership passage splits the router table in two. The table is "an instruction about what to read" supplied from outside, and "remains an outside contribution however it is executed inside"; the process of reading it at a call "runs inside the boundary" and "is the system's own today whoever wrote it". So a workflow may credit the agent with the routing it does and may not credit it with the routing policy it was given, and which is which is decided by where the boundary is drawn, not by where the file sits. Removing either clause gives a reading two judges struck. *Held; no count reaches it, and a contrast of the pasted skill against the live router under one reader would.*

## A trace is a read-out only where the transport records it

An active route "is read from the history, not from the result", and a part that reads or reports another part has a measurement's signature. A modules-opened field taken from the transport's record of the calls it served is a record of the history; the same field taken from the reader's own list of what it opened is an emission, and a prediction on it could be satisfied by a change in what the reader says it opened. The two can be told apart by a poke pair: delete a module file and both move; change only the reporting instruction and only the self-report moves. *Held.*

## The recursive-class aim is a declared input

(RC) is a class condition, not an obligation. "Repairing an obligation establishes that it was repaired; it establishes nothing about whether the obligation, or the question that led to it, was worth having. Where a claim invokes worth, the semantics takes a normative relation as a declared input and marks the place." That a workflow ought to scrutinize its own policies is the end goal's declared normative input; a zero on the operative-return count withdraws the workflow's claim to the recursive class and refutes nothing in the semantics. *Held, by file 11 alone (file 10 stated the normative relation only in the aesthetic entry).*

# Part XI — The record as history and receipts

A history is "a set of occurrences with an acyclic causal precedence and a physical interpretation supplying process occurrences, their ports, and the connections actually instantiated." A research record kept as this repository keeps it supplies the first two everywhere; it supplies the third for the runs a rig instrumented (finish reasons, call counts, tool audits) and not for its prose entries. Entries in results files that refer to a run are evidence leaves; receipts are derivation trees built by hand, a results file citing a rig file citing the raw returns; and the rule that raw evidence is never edited is what keeps them receipts. The owner's decisions are declared contracts and obligations; a job the skill tags *fixed* is a protected obligation held fixed for the comparison, with this difference: the semantics checks that a protected condition still holds on the occasions it covers, and the skill runs no test on a fixed job. A frozen plan is a document, not an event; it fixes the contract and the query so that the run it governs is an assessment at a fixed index, and a change to the plan is a new claim at a new index or a failure of the record. "Every patch records what it gives up" is the exposure rule of (P), carried by hand; the record declares no protected set, so it exposes every loss and checks no preservation. *All held if the practice's added job, that the record is part of the workflow by hand, is real; provenance fitted, since they were written with the conventions in view. Standing on the plan-and-assessment clause: unknown under W6.9.*

# Part XII — The placement of the operations

## The placement rule

Each operation of file 11's dependence order is placed by what it minimally needs to be instantiated: **at one call** if an execution with what its context carries suffices; **across calls** if continuity of a process or a carrier suffices; **only with a record or a harness** if it needs a history with precedence and receipts, a program around the agent, or a declared input from outside; **never** if the definition needs something no arrangement at the grain of text supplies. Two riders. First: a declared index the call's own context carries (the contract, the document's grain) does not move a row out of "at one call"; a declared index that is an attribution about the system making the claim (the boundary, the continuity) does, because ownership is grounded in what the boundary includes and never in the capability attributed, and an ownership and a capability justified only by each other have not supplied their place in the order. The contract's scope is itself a declared input, so the split is not the line between indices and inputs but between what the call's own context carries and what is an attribution about the system. Second: a column says what instantiating needs, not what establishing needs; where establishing needs more, the note says so. The rule is a construction; the theory permits the four cuts and contains no such classification. *Held if the first rider: a third swap, "an index declared by anyone outside the system moves the row", which neither of the rule's two failing swaps kills, would move eight rows into the record column. Standing: unknown under W6.9 on the mark.*

**The record column's gauge.** "Only with a record or a harness" is a bin that could absorb any row. Its gauge is a run's tool audit and its transport-recorded trace: an operation placed there that shows up in an arrangement with no record and no harness means the bin is swallowing a job.
