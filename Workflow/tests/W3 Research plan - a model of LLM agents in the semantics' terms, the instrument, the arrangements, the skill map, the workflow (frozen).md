## 1. The question, frozen

**The end goal, in the owner's words** (HV decision H6): "The end goal is an entire workflow that embodies the yet incomplete semantics theory HV is based on."

**"Embodies", given a term.** The theory collects its classes in Part XIV: "The base class: interpretations supplying these data with correct typing, satisfying physical realization wherever a physical attribution is made. The creative-episode class: base interpretations with an instance of (G) connected to a critical episode. The knowledge-creation class: an instance of (EK). The recursive class: (RC). The universal class: (U3)." A workflow embodies the theory, for this programme, when its operation supplies the base-class data (organizations, contracts, transports with a provenance, accounts checked by change) for the claims it handles, and when its own policies are scrutinizable in Part XIII's sense, which is the recursive class's condition. The programme does not claim the creative-episode, knowledge-creation or universal classes for any agent; phase 6 says what count would show the workflow fails the two it does aim at.

**The research question of this programme.** Which of the theory's objects does an agent built on a large language model instantiate at one call, which across calls, which only with a record or a harness around it, and which never; and, given that, which skills the workflow needs and where the boundaries between them lie.

**What is asked, over what range.** Asked: a model, written in file 10's terms, that says the above and can be caught out by runs this repository can make. Range: agents of the kinds this record has run (a reader under test through an API; a Claude Code subagent with tools; the agent that keeps this record), and the two arrangements the owner named (stateful, stateless). Not asked: what a transformer computes at the grain of its weights. The grain is a declared index: "**Indices, not primitives.** Grain \(\ell\), boundary \(\beta\), continuity \(\Omega\), and the contract \(C\) are declared indices. Every claim is relative to them; none is a predicate that could be true or false." (Part XIV). This programme declares its grain as text: what is in the context, what is emitted, and what changes in the emission when the context is changed. What organization a physical occurrence instantiates at any grain is the physical module's to supply: "The one thing (R) takes from outside is \(\operatorname{Org}_\ell(o)\): which organization a physical occurrence instantiates at a grain. That is supplied by the physical module, not by the semantics." (Part IV). Section 4, M1, says what this programme declares for it.

**The owner's six unknowns**, each quoted from H6 and given a number so the plan can be held to it:
- **Q1.** "creating a determinist harness that serves as an attention and token distribution system is difficult to implement without destroying the already latent LLM capabilities." Why, in the theory's terms, what "latent capability" is there, and which harnesses would not.
- **Q2.** "The capabilities seem to be centred around statefull vs stateless agents." What the difference is, in the theory's terms, and what it predicts.
- **Q3.** "built in context should consume part of the reasoning architecture specified in the semantics. As for exactly what is to be determined." Which of the theory's objects must live in the context at a call.
- **Q4.** "Externalising parts of memory are still important, and relevant to managing attention. As to how, I'm unsure." What external memory is, in the theory's terms, and how it bears on attention.
- **Q5.** "Whether LLMs guide attention in planning, exploration and execution is yet unknown. Maybe it needs to handle bits of attention and bits generation. But which, I'm not sure." Where an attention policy sits, what the theory requires of it, and which bits the agent should hold.
- **Q6.** "Which skills to have, and where the boundaries lie is the first step. Right now we have planning and HV." The skill map.

**The order the owner's note sets, both readings.** The note says "Which skills to have, and where the boundaries lie is the first step" and, two sentences on, "Nothing else can move forward without a sense of how LLMs fit into the larger semantics picture. First goal is the research." Read one way, "nothing else" means nothing besides the first step, so the map comes first and the model second. Read the other way, the sense of how LLMs fit is what the first step needs, so the model comes first. This plan takes the second reading, for a reason that is the plan's own and not the theory's: the map assigns the theory's operations to holders, and cannot assign an operation to a skill without knowing which operations an agent can carry at a call, which is what the model says; the theory's nearest sentence is Part XII's "A theorist's description of a protocol is not the system's possession of it." Part XIV's dependence order, read as an order of work, would favour the first reading, since the account predicates the map's rows carry come before (R) and retention in that order. The choice is shown wrong by the owner's word, and by nothing else; the map is sketched now (section 6) so that phase 1 is not written to fit it.

| 2. The reading | A results file: every part of the model read against the evidence in hand, by a coverage map fixed before reading | A reading, not a test | the owner's word alone; the owner's material on the harness of Q1 is read if supplied and recorded as an unreached part if not |
| 3. The instrument | An authority file: the marking plan for the arrangements: the three fields H64 struck, reworded; criteria for the three new fields this programme needs; a question-identity field; per-field agreement re-established between two blind markers on the 96 marked reports already in hand | A test of the marking, on evidence already spent; no key, no fresh documents | the owner's word |

**Why the model comes before the map:** section 1, both readings. The map is sketched in section 6 now, marked as a hypothesis and as an unquoted sketch phase 1 must trace, so that phase 1 is not written to fit it.

**Why phase 2 is a reading and not a test.** The evidence in hand was read before this plan existed, except the 99 light-marked reports, which are held out and stay so; a model written after reading the rest cannot be tested on it ("A case a part was fitted on cannot confirm that part", file 33). Phase 2 has one job: to find where the record already contradicts the model. A recorded result that contradicts a part is a test the record ran once; Planning `changes.md` says a fault seen once forces a repeat under the unchanged version, so the contradiction is written into phase 4 as a prediction and the model is changed after phase 4, not after phase 2. The coverage map (which piece of evidence bears on which part) is fixed in phase 2's plan before the reading, so that "no contradiction found" can be told from "no evidence reached it". The W2 judging round itself, five fresh calls each handed one task, is entered in the coverage map as a coarse partition observation for M8's partition clause: the round produced part-by-part marks in quantity and no pulling pairs or same-explanation verdicts of its own, and the results file says whether that is a loss or an unasked question.

**Why the instrument comes before the arrangements.** Everything the programme wants to say about an arrangement is read off what changes between reports under changed inputs, and that needs a measuring device that agrees with itself. The record's one device ended with three fields struck: "shape's PART boundary (a written rule is needed), 'turned own test' (the criterion is reworded or dropped), the same-explanation verdict as a count (kept as quotes only)" (HV H64), and Planning file 2 says a struck field carries no claim until its criterion is reworded and a third reading has run. The draft W1 had rested its two load-bearing predictions on the struck count. Repairing the instrument spends no fresh document, no key and no reserve: the 96 marked reports are in hand. Part II licenses treating the instrument as a component with its own signature: "a **measurement** has a signature invariant under interventions on the measured port and variable under edits to the measuring relation". No field carries an arm difference in phase 4 unless it agreed in phase 3.

**Why phase 4 is the first test of the model.** The model's load-bearing predictions (section 5) are about what changes in an agent's report when what it is given is changed, across arms. What such a run can settle is bounded by Derivation 9: "**Claim.** If \(M_0,M_1\) have the same input–output projection and differ on an account claim, no function of the projection agrees with the claim on both. ... The same holds for attribution from emitted text and for use inferred from delivery logs." So phase 4 separates arrangements by their projections: where two arms emit differently under the same inputs, they are different organizations ("Two systems with identical outputs and different internal routes are different organizations here, and the semantics says so", Part 0). It does not settle what any arrangement instantiates, and agreement between two arms does not show they instantiate the same thing; it shows that no admitted change on that contract separates them, which is Derivation 2's report: "Underdetermination of an account by a contract is not a failure of the semantics to decide; it is the semantics reporting that the contract does not contain the distinction." The instantiation claims of M4, M5 and M6 are therefore unknown at this grain, with *look inside* named as the test that cannot bite on it.

## 4. The first sketch of the model, with what would count against each part

This is the hypothesis phase 1 builds out, criticises and freezes. It is written now so that the predictions are on record before the building. Each part gives the sentence of file 10 it rests on, with its Part, and the finding that would count against it. Where a part is a construction, it is marked so with the passages it is built from. The theory's own caution on declaration applies throughout: "Declaration is permitted only as a modelling convenience, and a claim about creativity cannot rest on it." (Part 0). The two indices every ownership predicate below carries are declared first.

**The indices declared.** *Boundary* \(\beta\): the system is the reader and the program that hands it its context (the transport); the record, the corpus and the owner are outside it. Under this boundary a policy fixed in the transport's program is outside what the reader can make a target; a policy carried as text in the context is inside. *Continuity* \(\Omega\): what persists between one execution and the next. For arm (a) of phase 4, the agent's process and its transcript, carried by its own harness; for arms (b), (c) and (c'), only the carrier text the rig hands over; for arm (d), only the document and the frozen question. These two are declared indices (Part XIV, quoted in section 1), and every claim below is relative to them.

**M1. A call is one execution; the context is what it reads; the emission is what it writes; and the organization the carrier text instantiates at the grain of text is the model's declared physical input.** Part XII: "A substrate is a physical system; an attribute a set of its states; a task a permitted input-to-output attribute transformation with explicit resources and side effects." One request to the language model is one execution \(\eta\) of a protocol \(\pi\); the context window is the set of occurrences ("An **occurrence** is a physically located carrier.", Part IV) the execution reads, and the emitted text is the occurrences it writes. What (R) needs from outside, \(\operatorname{Org}_\ell\), is declared here at the grain of text: the organization a call's carrier text instantiates is the one whose ports are the passages of the context and the emission and whose components are the dependences between them that the admitted edits (change a passage of the context; withhold one; add one) expose. This is a declared input in the theory's own sense and the model rests no claim about creativity on it. *Mark:* loose, provenance asserted. M1 is a free modelling choice with near neighbours that change the arms: "one call" as one request, as one agent turn with its tool calls, or as one session. This plan takes one request as one execution. Arm (a) of phase 4 is then many executions inside one process, whose continuity is the transcript its harness carries; arm (b) is many executions whose continuity is the transcript the rig hands over; the two differ only in who carries the transcript, and P4.1 tests whether that difference shows. *Would count against it:* a judge showing that the declared \(\operatorname{Org}_\ell\) is not an organization in Part II's sense (no ports, no components, no admitted edits), or that a claim in M4 to M10 about construction rests on the declaration (section 9).

**M2. The organization the weights instantiate admits a selected transport.** Part IV's definition: "**Selected.** There is a population \(\mathcal T\) of candidate transports, a variation operator \(\mu\) on \(\mathcal T\), a finite history \(H\subseteq C\) of edit–boundary pairs actually encountered, and a survival condition requiring fidelity on \(H\). The transport \(t\) is a member of \(\mathcal T\) that survived. No member of the history represents \(t\), \(H\), or the survival condition." A transport runs between organizations and has no components of its own; the components are the organization's. Training fits the first three clauses: the population is the parameter settings reached, \(\mu\) the update, survival the loss condition. \(H\) is a set of edit–boundary pairs, not of documents: for a training run, an edit is one setting of the context ports (one training example as the context), the boundary its target continuation, and \(C\) the set of such settings the model's serving admits; \(H\) is the finite set of those actually seen. The fourth clause, that no member of \(H\) represents \(t\), \(H\) or the survival condition, is *unknown*: a training corpus that contains descriptions of gradient descent and loss functions has members whose authors built them with the target in view, and whether such a member represents the survival condition in (R)'s sense is the check that would settle it, named here and not run. One clause of Part 0 does not fit as written: there the selected correspondence is "produced by blind variation and survival on a history of predictions"; a training update is not blind. The formal definition needs no blindness and Derivation 3's proof uses none, so M2 rests on the formal definition. *What follows* is Derivation 3: "A correspondence produced by selection is faithful where it was tested and unconstrained where it was not." Its proof rests on a premise M2 must carry: "The component relations \(L_j(a,b)\) are supplied independently for each \((a,b)\)." A parametric family with tied weights is the shape file 10 names as what would refute Derivation 3 (Part XV: "**A non-fallible selected transport.** A selection history \(H\subsetneq C\) whose survivor is determined on \(C\setminus H\). This refutes Derivation 3."). So M2 rests on attack point (D): "**(D) Genesis.** Show either that a selected transport can be non-underdetermined on unseen changes (against Derivation 3) ..." (Part 0). If (D) succeeds for language models, M2's consequence falls, and with it the model's ground for saying nothing about a reader's behaviour off its history; the programme would then record Q2's and Q4's answers as resting on a refuted derivation and re-derive them from the arms alone. *Mark:* held if (the independence premise and the fourth clause), provenance built. *Would count against it:* a judge showing a reader's transport family violates independence, that is, that survival on \(H\) does constrain behaviour off \(H\); or a member of a training history shown to represent the survival condition.

**M3. Nothing about what an agent instantiates is read off its emission at a fixed input; a difference in emission under a changed input shows two arrangements are different organizations; agreement shows only that the contract does not contain the distinction.** Derivation 9 (quoted in section 3), Part 0's "Two systems with identical outputs and different internal routes are different organizations here", and Derivation 2's consequence (quoted in section 3). A report that uses the skill's words is a carrier that carries the same words: "Occurrences are not identified by carrying the same words; contents are not identified by having the same outputs." (Part IV). *Mark:* held, provenance built; it is a theorem of file 10 applied, and what it rules out is a test design. Phase 4's arms are built to it and its predictions of difference are what the run can settle.

**M4. A skill file is a carrier; whether a reader represents its content is a fidelity fact with a history.** (R): "An occurrence \(o\) **represents** content \(c\) at grain \(\ell\) when the organization that \(o\) instantiates under the physical module, at grain \(\ell\), admits a transport to \(c\) that is faithful on \(c\)'s contract and whose provenance is selected or constructed" (Part IV). A reader with the skill in its context represents the skill's method when its reports respond to edits of the skill's words as the method says they should, over the changes the skill's contract admits. The record holds one version change made as two edits (file 30 to file 31, HV H58): under file 30 one recurrence of break 2 in six runs and none in twelve under file 31; the redirect to the proofs tests in five of six runs on the derived-conclusion case; a load-bearing premise moving from *borrowed* to *fixed* in four of six, which the record leaves as the owner's call; and, under file 31, two responses the method does not license (*Asserted* as a mark; *fixed* on a derivation), one run each, in the second reader (H62). That evidence runs both ways and was written with in view: it is fitting, and cannot confirm M4. Copying the method's form (HV project story, entry 54: "the method's form in 32 of 32 skill-mode reports") is not, by itself, evidence of representation, because a carrier is not a representation (Part IV, quoted in M3). *Mark:* held if, provenance fitted. The test that would hold it: one clause of the skill edited in a copy made for the test, with the prediction written first, against the frozen file, on documents no run has read; a copy edited for a test is not an edit to the authority, and phase 4's plan says whether it runs that arm (its box is named in section 5 as optional, with its falsifier fixed). *Would count against it:* a reader whose reports do not change under any edit of the skill's words while still doing the skill's work.

**M5. Stateful and stateless differ in what the continuity contract carries; the difference tracks what is represented at each call, not the label.** *Construction*, built from three passages file 10 does not join: Part XII's "**Owned capability.** \(\operatorname{Can}_{\Omega,\beta}(\xi,T;\chi)\) requires an owned retained realization or an owned, physically admitted, finite construction of one under the same continuity and resource contract. A theorist's description of a protocol is not the system's possession of it."; Part XII's retention fixed point (CT2), which says which states have executions that complete and return into the constructor attribute \(C\) and nothing about what those states carry; and Part IV's requirement on a constructed transport that "\(t\), or the organization it targets, is available as a represented target", over Part X's "an actual subhistory owned by \(s\)". The construction: a stateful agent is one whose constructor attribute (an attribute is "a set of its states", Part XII) is the set of states carrying the represented targets of its unfinished work; a stateless agent's attribute between calls is only what its carrier text carries. So the model says: (i) a fresh call handed the whole transcript and the stateful agent differ on whatever the continuity contract carries and the transcript does not; at the grain of text, if the transcript carries everything the process carried, no admitted change on the contract separates them and they are one account at that grain (Derivation 2's consequence), which settles nothing about what either instantiates; (ii) a fresh call handed a summary differs from the stateful agent exactly on the fields whose work needs a target across steps that the summary did not carry (the best rival, pairs that pull, check the patches, the same-explanation verdict), and not on fields whose work is done within one step (a part's mark by remove, swap and poke). The sorting of fields into within-step and cross-step is a part of the model, written here before any run, and is not re-sorted on the reports that break it (section 8). *Mark:* held if (by P4.1 and P4.2, and only on fields phase 3 certifies), provenance built. *Would count against it:* arm (a) and arm (b) of phase 4 disagreeing on a certified field on more documents than two repeats of arm (a) disagree, by the rule in P4.1; or arm (c) losing the within-step fields.

**M6. The context holds the construction target; a target can also come from the weights, and then its provenance is fitted.** Part IV requires, for a constructed transport, that "\(t\), or the organization it targets, is available as a represented target"; that requirement is placed on an episode, not on one call, and this plan indexes it to the owned subhistory of the arm (for arm (a), the process; for the fresh-call arms, the one call). The draft W1 had said what is not in the context cannot be built on at that call; the record contradicts that: readers have named targets absent from the document and from any file they read, and flagged them as from outside the text (HV H62's OUTSIDE flags; the recall paragraph of file 54). By M2 the weights are a carrier at every call, and a target that comes from them is fitted: held only on the changes it has met. So the model's answer to Q3 is: the context must carry the frozen question with its change list and the parts under test, which is this plan's own requirement (a construction on Part III's tuple, which says what a question is and not what an execution must read), and the construction target, which is Part IV's; everything else (the record, the corpus, earlier reports, the theory) may sit outside and come in by a transport, or come from the weights with fitted provenance. *Mark:* held if, provenance built. *Would count against it:* arm (f) of phase 4, the context with the change list withheld, moving no within-step field (then the change list is idle in the context and the list is too long); or a rival built with its target in neither the context, nor any file or command output the audit shows, nor flagged by the reader as from outside, which would be a target with no carrier at all.

**M7. External memory is a set of occurrences outside the context, brought in by a transport whose provenance is declared unless the agent constructs the query; it bears on attention by deciding which targets are represented at the next call.** Part IV: "A declared transport does not make an occurrence represent anything; it makes a modeller assert that it does." A lookup the designer wrote is declared; a query the agent built from a represented difficulty is constructed. The record of this repository is such a memory in part: Part IX's definition is "A history \(h\) is a set of occurrences with an acyclic causal precedence \(\prec_h\) and a physical interpretation supplying process occurrences, their ports, and the connections actually instantiated." The log supplies occurrences and an acyclic precedence; the third clause, the physical interpretation, the record does not supply, and the reading of the record as a history is a construction to that extent. Its receipts: "An evidence leaf is a reference to an event with an interpreted claim. A receipt is a derivation tree over leaves." (Part IX); the entries in results files that refer to a run are leaves, not the files. The convention "read the record first" is its retrieval policy, declared. This is the model's answer to Q4. *Mark:* held if, provenance built. *Would count against it:* a judge showing the record fails the two clauses it is said to meet; or arm (c') of phase 4, fresh calls each handed a carry-over note the previous call wrote, losing no fewer cross-step fields than arm (c), the program-written summary: then who writes the carrier does not matter at this grain and the declared-against-constructed distinction does no work for Q4.

**M8a. A harness that sets a port the model's components assign replaces that component; the set port is fixed and the other ports of that component's footprint lose the relation it imposed on them.** Part II: "An edit that sets a port replaces the component assigning that port; it does not add an equation beside an incompatible one." and "A deleted component imposes the full relation on its ports." A harness that writes tokens, or fixes the shape of the emission (a prefilled report skeleton; a closed list the marks must come from), sets ports that the organization's own components assign; each such edit replaces a component, and the other ports in that component's footprint lose the constraint it carried. That loss is what the harness costs. The "latent capability" the owner's Q1 names is, in the theory's terms, Part XII's owned capability \(\operatorname{Can}\) on the tasks the unconstrained organization could carry; what is lost is the constraint that carried it. Which ports the components assign is \(\operatorname{Org}_\ell\) of the transformer, which the programme declares only at the grain of text (M1): so at this grain M8a reaches the emission ports (what is written) and not the attention half of Q1 (what is attended to), which has no port here. *Mark:* borrowed from the physical module for the attention half, and unknown for the emission half until arm (e) runs; provenance built. This is an eliminative claim in shape (why a capability is absent under the harness), and the theory marks its treatment of such claims as exposed: "This is the semantics' treatment of eliminative explanation; it is offered as adequate and is listed under attack (B) as a place where it may not be." (Part VII). If (B) succeeds, M8a's answer to Q1 has no treatment in the theory and Q1 is reported under P1.2 as an unknown the theory as written cannot reach. The difficulty the owner reports is a difficulty, not a recorded failure, and is no barrier proof: "A finite list of failures is not a barrier proof; a bypass refutes a proposed barrier." (Part XIII). The bypass the model names is a harness confined to what the model reads; arms (b) and (c) of phase 4 are such harnesses, and the model predicts they lose no within-step field. *Would count against it:* arm (e) matching arm (a) on the within-step fields as closely as arm (b) does; or the owner's harness material (phase 2) showing the loss under a harness that set only what the model reads.

**M8b. A harness that partitions a task across calls, so that no call sees the others' parts, loses what only the parts held together.** Part VI, not (F2): "A block may be critical while no singleton in it is." and "**Interference.** \(\Gamma=\{a,b\}\), \(\mathsf S=\{\{a\}\}\): the full candidate fails although a subset succeeds. Success of a subset does not imply success of the whole". A call handed one test and one part cannot run a test whose object is a pair or the whole (pairs that pull; the best rival; the same-explanation verdict), so those results fall while the part-by-part marks stand. **What the model does not claim.** That any agent belongs to the theory's classes: "It does not prove that any human, machine, institution, or lineage belongs to the classes defined. ## 7. What counts as each outcome, decided before reading

- **A row of the model's word list holds** when file 10's quoted sentence, at the Part named, says what the row says in the theory's terms, read no wider than written. It is **loose** when the row would survive a rewording that named a nearer passage. It is **a construction** when the theory permits the object but does not contain it (as "hard-to-vary over scope: Pres(F) under edits to the contract" is permitted by Derivation 5 and contained nowhere), and it is marked so with the permitting passages. It **contradicts** when file 10 says otherwise in a sentence the judge quotes.
- **A part of the model is marked** with the eight marks of HV file 33, by a judge, with the holder quoted (a sentence of file 10, a result in the record, or a prediction of section 5 that could fail), and its provenance beside it. *Held if* and *unknown* follow file 33's readings.
- **A field agrees between two runs** when the marker's record for the field is the same (RAN or not; the same mark on the same part; the same pairs named; the same rivals built; the same question kept) on the same document. Agreement is a count of documents, by field, never summed across fields or arms.
- **A target** is what Part IV means: "\(t\), or the organization it targets"; for a rival built, the explanation it rivals; for a pulling pair, the two parts named. A target has a carrier when it is in the context, in a file or command output the audit shows the call read, or flagged by the reader as from outside the text (then its carrier is the weights, M2).
- **A reading in phase 2 contradicts a part** when a recorded result, quoted, is something the part says will not happen, or the absence of something the part says will. A result the part merely does not mention is not a contradiction and is not counted as support.
- **The owner's word** is the sentence the owner writes, recorded in Decisions here as written; a sentence recorded elsewhere in the record is cited as such.

## 10. Known weaknesses, stated before use

- **The writer of the model is an agent of the kind the model is about,** and so are the judges and the readers. The theory allows a system to be wrong about its own capacities ("Systems can be wrong about their transports, their observations, their criticisms, and their own capacities", Part I); the arms of phase 4 are the only check that does not pass through an agent's own report of itself, and Derivation 9 bounds what they settle (section 3).
- **The grain is text.** \(\operatorname{Org}_\ell\) of a transformer is outside the programme by choice (section 1), and M8a's attention half is borrowed from the physical module and cannot be settled here.
- **The owner's harness observation is claimed, not in the record.** Phase 2 asks for the material; until it comes, M8a's answer to Q1 rests on the theory and on arm (e).
- **Two frozen skills pull against each other here,** and this plan says which gives way: Planning file 2 requires every prediction to name a falsifying count; HV file 33 forbids counting parts as a verdict. Counts in this plan are falsifiers of predictions and never verdicts on a part or on the whole; where a threshold has no reason in the record it is a free choice and is marked so (the "at least two of three", "44 of 48", "40 of 48", "46 of 48", "plus three", "by at least three" of section 5 are free choices set against H64's 38 of 48 for the struck field, 48 of 48 for recurrence and 84 percent for RAN-versus-not; the coarse claim each stands for is that a field must agree between markers more often than the arm difference it is asked to carry).
- **Three per box is small** (Planning file 2: "0 of 6 is compatible with a fault that fires one time in ten"). Phase 4's counts are read as counts.
- **Phase 4 is the first reader run under file 33.** The record shows a version change can itself produce new faults (two in Sonnet 5 under file 31, one run each, H62); the optional control box under file 31 is the only way to tell a fault of the new wording from a fault of an arm, and the marker names the layer at fault on every report, as plan 52 and Planning file 2 require: a failure is the skill's when its wording pushed the reader there, whether or not it appears in every arm.
- **Swap and poke are the record's least reliable cells** (36 and 35 of 48 between markers, H64), and they are two of the three within-step fields; P3.5 says what happens if the instrument cannot certify them.
- **Every arm is a new rig.** The H61 transport ran one call per report; no arm of phase 4 has a precedent, and the phase has a list of programs to write, one per arrangement.
- **The judges of this plan read the record the plan was written from.** The rival-building judge and the file-10 judge are the two that could find what the writer could not, and did (M8's fusion; Derivation 9's direction).

## 11. What this plan does not test

- Anything at the grain of weights or activations.
- Whether any agent understands, is creative, or creates knowledge in the theory's senses (Deploy, (G), (EK)). The model names what would have to be shown; no phase here shows it.
- The skill's own faults. HV file 33 is frozen; a reader's failure under it in phase 4 is charged to the layer the marker names (the document, the skill, the reader); when it is the skill's wording, it is held for the HV project and written in RELATIONS, never fixed here.
- The semantics itself. Where the model finds file 10 cannot reach one of the owner's unknowns, that is recorded as an ask for the owner, never as a change; the theory's audit is the Semantics project's.
- The other model (the one that audits the semantics). It is not used in this programme; if a phase wants it, that phase's plan says so and the Semantics project's rules for handing it things apply.
- The generation half of Q5 (Build), and the attention half of Q1.

## 13. Traps

- **Reading M1 to M10 as the model.** They are the sketch the judges cut once and phase 1 builds. The model is phase 1's file.
- **Counting the six unknowns answered as a score.** One unknown the theory cannot reach matters more than five it can; P1.2 names them.
- **Letting phase 2 count as a test.** It reads the fitted evidence; the first test of the model is phase 4.
- **Reading a reader's report as what the reader instantiates.** Derivation 9 bounds it; only a difference between arms under changed inputs is evidence, and agreement settles nothing about instantiation.
- **Reading an arm difference off a field phase 3 did not certify.**
- **Naming the readers' failures under the skill as the skill's, or the skill's as the arm's.** The marker names the layer on every report.
- **Writing the word list rows wider than file 10 writes them, or at the wrong Part.** The H69 check found the first fault twice; the W2 round found the second twice; every row quotes and names its Part, and the program checks both.
- **Assuming a harness cannot work because one was difficult.** Part XIII: a finite list of failures is not a barrier proof, and a difficulty is not a recorded failure.
- **Fusing the two losses of M8.** Component replacement (M8a) and partition (M8b) are tested by different arms and fall separately.
- **Moving a phase's count into this file after the fact.** Counts belong to the phase plans; this file fixes the shapes of the falsifiers and is not edited after the owner's word on phase 1.
