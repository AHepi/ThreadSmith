## 1. The question, frozen

**The end goal, in the owner's words** (HV decision H6): "The end goal is an entire workflow that embodies the yet incomplete semantics theory HV is based on."

**The research question of this programme.** Which of the theory's objects does an agent built on a large language model instantiate at one call, which across calls, which only with a record or a harness around it, and which never; and, given that, which skills the workflow needs and where the boundaries between them lie.

**What is asked, over what range.** Asked: a model, written in file 10's terms, that says the above and can be caught out by runs this repository can make. Range: agents of the kinds this record has run (a reader under test through an API; a Claude Code subagent with tools; the agent that keeps this record), and the two arrangements the owner named (stateful, stateless). Not asked: what a transformer computes at the grain of its weights. File 10 puts that outside the semantics: "The one thing (R) takes from outside is \(\operatorname{Org}_\ell(o)\): which organization a physical occurrence instantiates at a grain. That is supplied by the physical module, not by the semantics." This programme works at the grain of text: what is in the context, what is emitted, and what changes in the emission when the context is changed.

**The owner's six unknowns**, each quoted from H6 and given a number so the plan can be held to it:
- **Q1.** "creating a determinist harness that serves as an attention and token distribution system is difficult to implement without destroying the already latent LLM capabilities." Why, in the theory's terms, and which harnesses would not.
- **Q2.** "The capabilities seem to be centred around statefull vs stateless agents." What the difference is, in the theory's terms, and what it predicts.
- **Q3.** "built in context should consume part of the reasoning architecture specified in the semantics. As for exactly what is to be determined." Which of the theory's objects must live in the context at a call.
- **Q4.** "Externalising parts of memory are still important, and relevant to managing attention. As to how, I'm unsure." What external memory is, in the theory's terms, and how it bears on attention.
- **Q5.** "Whether LLMs guide attention in planning, exploration and execution is yet unknown. Maybe it needs to handle bits of attention and bits generation. But which, I'm not sure." Where an attention policy sits, and what the theory requires of it.
- **Q6.** "Which skills to have, and where the boundaries lie is the first step. Right now we have planning and HV." The skill map.

The owner also said what comes first: "designing a model of LLMs within the language of the semantics needs to be resolved" and "Nothing else can move forward without a sense of how LLMs fit into the larger semantics picture." So the model (phase 1) comes before the skill map (phase 4), though Q6 is called the first step; section 3 says why the order is not a contradiction.

## 3. The shape of the programme

Five phases. Each is a numbered plan of its own when its turn comes, frozen before it runs, on the owner's word. This file fixes the order, what each phase must produce, what it may and may not count as evidence, and the predictions that the programme as a whole can fail on.

| Phase | Produces | Kind of work | Waits on |
|---|---|---|---|
| 1. The model | An authority file: the model of an LLM agent in the theory's terms, with its own word list and, frozen first, the predictions it makes | Building (HV `building.md`) and judging (Opus 5 judges, five at most) | the owner's word after this plan is frozen |
| 2. The reading | A results file: every part of the model read against the evidence in hand, by a coverage map fixed before reading | A reading, not a test | the owner's word; the owner's own material on the harness of Q1 |
| 3. The first run | A frozen plan and results: the arms that separate stateful from stateless, and the partition harness, on documents no run has read | A test, with readers under test and blind second marking | the owner's word and a key |
| 4. The skill map | An authority file: which skills, each with its contract, and the boundaries; a list of what no skill holds | Building and judging | the owner's word after phase 3's results |
| 5. The workflow | An authority file and a first run on the reserve | Building, then a test | the owner's word after phase 4 |

**Why the model comes before the skill map, though the owner called the map the first step.** The owner's sentence "Nothing else can move forward without a sense of how LLMs fit into the larger semantics picture" puts the model first, and the map second, in the same note. The theory gives the reason in its own dependence order (Part XIV): what a skill is for is one of the theory's operations (checking an account, finding a question, building, criticising, repairing, keeping receipts), and which of those an agent can carry at one call is exactly what the model says. A map drawn before the model would place the boundaries by habit. The map is still sketched in section 6 now, as a hypothesis with what would count against it, so that phase 1 is not written to fit it.

**Why phase 2 is a reading and not a test.** Every run in the record was read before this plan existed; a model written after reading them cannot be tested on them (the skill's own rule: "A case a part was fitted on cannot confirm that part"). Phase 2 has one job: to find where the record already contradicts the model, so that the model that reaches phase 3 has met the evidence in hand. Its coverage map (which piece of evidence bears on which part) is fixed in phase 2's plan before the reading, so that "no contradiction found" can be told from "no evidence reached it".

**Why phase 3 is the first test.** The model's load-bearing predictions (section 5, M5 and M8) are about what changes in an agent's report when the context it is given is changed, across arms. That is a run, not a reading. It is also the theory's own rule for the kind of claim being made: "The same holds for attribution from emitted text and for use inferred from delivery logs" (Derivation 9). Nothing about what an agent instantiates is read off one report; it is read off what changes between reports under admitted changes.

## 4. The first sketch of the model, with what would count against each part

This is the hypothesis phase 1 builds out, criticises and freezes. It is written now so that the predictions are on record before the building, as the skill requires ("Looking before writing down what would count against you"). Each part is given the sentence of file 10 it rests on and the finding that would count against it. Parts are numbered M1 to M10. Where a part is a modelling frame rather than a claim, it is marked as declared, and the theory's own caution applies to it: "Declaration is permitted only as a modelling convenience, and a claim about creativity cannot rest on it."

**M1. A call is one execution; the context is what it reads; the emission is what it writes.** (Declared frame.) In Part XII's terms, the language model with its serving code is a protocol \(\pi\) on a substrate; one call is one execution \(\eta\); the context window is the set of occurrences ("An **occurrence** is a physically located carrier") the execution reads, and the emitted text is the occurrences it writes. What organization the execution instantiates, \(\operatorname{Org}_\ell\), is the physical module's and is not claimed here. *Would count against it:* nothing, because it is a frame; it is the one part of the model that is declared, and phase 1 keeps it to this one.

**M2. The weights are a selected transport.** Part IV's definition: "There is a population \(\mathcal T\) of candidate transports, a variation operator \(\mu\) on \(\mathcal T\), a finite history \(H\subseteq C\) of edit–boundary pairs actually encountered, and a survival condition requiring fidelity on \(H\). The transport \(t\) is a member of \(\mathcal T\) that survived. No member of the history represents \(t\), \(H\), or the survival condition." Training fits every clause: the population is the parameter settings reached, \(\mu\) the update, \(H\) the training history, survival the loss condition, and nothing in the training data represents the model or the loss. One clause of Part 0 does not fit as written: there the selected correspondence is "produced by blind variation"; a training update is not blind. The formal definition needs no blindness and Derivation 3's proof uses none, so M2 rests on the formal definition and says so. *What follows* is Derivation 3: "A correspondence produced by selection is faithful where it was tested and unconstrained where it was not." So the model predicts nothing about a reader's behaviour on a change outside its history from its survival alone, and any claim in the workflow that a reader "will" do a thing it was never shaped against is unfounded in the theory. *Would count against it:* a judge showing that a training update fails one of the four formal clauses; or that Derivation 3's proof needs the blindness the formal definition leaves out.

**M3. What an agent instantiates is never read off its emission; it is read off what changes.** Derivation 9: "If \(M_0,M_1\) have the same input–output projection and differ on an account claim, no function of the projection agrees with the claim on both. ... The same holds for attribution from emitted text and for use inferred from delivery logs." So every claim this programme makes about an agent is tested by an admitted edit to what the agent is given and the change in what it emits, over the change list of that claim. A report that uses the skill's words is a carrier that carries the same words; "Occurrences are not identified by carrying the same words" (Part IV). *Would count against it:* nothing in the world; it is a theorem of file 10 applied. What it rules out is a test design, and phase 3's arms are built to it.

**M4. A skill file is a carrier; whether a reader represents its content is a fidelity fact with a history.** (R): "An occurrence \(o\) **represents** content \(c\) at grain \(\ell\) when the organization that \(o\) instantiates under the physical module, at grain \(\ell\), admits a transport to \(c\) that is faithful on \(c\)'s contract and whose provenance is selected or constructed." A reader that has the skill in its context represents the skill's method when its reports respond to edits of the skill's words as the method says they should, over the changes the skill's contract admits. The record holds two such edits: file 30 to file 31 changed the readers' reports at the two breaks (HV H57 to H59); that is evidence of the form (R) asks for, on two edits and nothing wider. Copying the method's form (HV log 54: "the method's form in 32 of 32 skill-mode reports") is not, by itself, evidence of representation: "Reconstruction by a learner is construction; relay is not" (Part X). *Would count against it:* a judge showing that (R) cannot be applied to a reader's report organization at the grain of text at all; or phase 3 finding a reader whose reports do not change under any edit of the skill's words while still doing the skill's work, which would mean the work is coming from somewhere the skill is not.

**M5. Stateful and stateless differ in retention, and the difference tracks what is represented at each call, not the label.** Part XII: "**Owned capability.** \(\operatorname{Can}_{\Omega,\beta}(\xi,T;\chi)\) requires an owned retained realization or an owned, physically admitted, finite construction of one under the same continuity and resource contract. A theorist's description of a protocol is not the system's possession of it." And Part X's construction needs "an actual subhistory owned by \(s\)" in which the target is "available as a represented target". A stateful agent is one whose executions return into a state that carries the represented targets of its unfinished work (the retention fixed point, CT2); a stateless agent's state between calls is only what its carrier text carries. So the model says: (i) a fresh call handed the whole transcript instantiates, at the grain of text, what the stateful agent instantiates, and the two will not differ on any field; (ii) a fresh call handed a summary differs from the stateful agent exactly on the fields whose work needs a target across steps that the summary did not carry (building the best rival, pull, check the patches, the same-explanation verdict), and not on fields whose work is done within one step (a part's mark by remove, swap and poke). *Would count against it:* arm (a) and arm (b) of phase 3 disagreeing on any field by more than two runs of arm (a) disagree with each other; or arm (c) losing the part-by-part fields the model says need no cross-step target.

**M6. The context holds the represented targets, the boundary conditions and the change list of the current question; what is not represented cannot be built on at that call.** Part IV: a constructed transport needs an episode "in which \(t\), or the organization it targets, is available as a represented target"; Part III: a question carries its contract \(C\), its baseline \(b_0\) and its obligations \(O_p\). So the part of the reasoning architecture the context must consume is exactly: the frozen question with its change list, the parts of the explanation under test, and any target a construction at this call is to bind to. Everything else (the record, the corpus, earlier reports, the theory itself) may sit outside and come in by a transport. This is the model's answer to Q3, and it is a claim, not a frame. *Would count against it:* an arm in which a reader builds a rival or names a pulling pair whose target was not in its context at that call and not in any carrier it read; the tool audit says what it read.

**M7. External memory is a set of occurrences outside the context, brought in by a transport whose provenance is declared unless the agent constructs the query; it bears on attention by deciding which targets are represented at the next call.** Part IV: "A declared transport does not make an occurrence represent anything; it makes a modeller assert that it does." A lookup the designer wrote is declared; a query the agent built from a represented difficulty is constructed. The record of this repository is such a memory: "A history \(h\) is a set of occurrences with an acyclic causal precedence \(\prec_h\)" (Part IX), with receipts ("An evidence leaf is a reference to an event with an interpreted claim. A receipt is a derivation tree over leaves"); the convention "read the record first" is its retrieval policy, declared. This is the model's answer to Q4. *Would count against it:* a judge showing that the record fails Part IX's definition of a history (for instance, that its precedence is not acyclic, or that its leaves do not refer to events); or phase 5 finding that a workflow with a constructed retrieval does no differently from one with the declared lookup on a task the model says needs a represented target.

**M8. A harness that sets what the model's components assign deletes those components; one that sets what they read does not.** Part II: "An edit that sets a port replaces the component assigning that port; it does not add an equation beside an incompatible one." and "A deleted component imposes the full relation on its ports." Part V: "(F2) prevents a set of locally correct pieces from hiding a lost shared constraint." So a deterministic harness that sets tokens or attention sets ports that the selected transport's own components assign; each such edit replaces a component with the full relation, and the shared constraints those components carried go with them. The loss tracks *which* ports are set (the outputs of the model's components: what to attend to, what to emit next), not *how much* is set. A harness that sets only what the model reads (the context, the boundary conditions, the question) replaces nothing. And a harness that partitions a task across calls so that no call sees the others' parts deletes the shared constraints between parts: the whole-explanation results (pairs that pull, the best rival, the same-explanation verdict) fall while the part-by-part marks stand. This is the model's answer to Q1. It also says, with Part XIII, that the owner's failed harness is not a barrier: "A finite list of failures is not a barrier proof; a bypass refutes a proposed barrier"; the bypass the model names is a harness confined to the ports the model reads. *Would count against it:* the partition arm (d) of phase 3 matching arm (a) on the same-explanation verdicts and the pulling pairs; or the owner's harness material (phase 2) showing a loss under a harness that set only inputs.

**M9. An attention policy is an aspect of practice and must be scrutinizable by the agent for the workflow to have recursive capacity; where it sits is decided by what can make it a target.** Part I: "**Recursive scrutiny with operative return.** Any aspect of a system's practice — a question, a contract, a transport, a method, an attention policy — can become a target, and the result must be able to change how the system proceeds." Part XIII: "An aspect \(d\) of a system's practice is scrutinizable at \(\xi\) when there is an owned, admitted continuation in which a description of \(d\) becomes a represented target, criticism can be directed at it, and the result can affect its operative use." So the model's answer to Q5 is not "the LLM guides attention" or "the harness does" but: a policy carried as text the agent can read, criticise and change (a router table in a skill; a plan) is scrutinizable by the agent; a policy fixed in a harness is scrutinizable only by its designer. Which bits of attention and which bits of generation the agent should hold is then the question of which policies the workflow needs to be able to criticise from inside. *Would count against it:* a judge showing the quoted definition does not reach a policy carried as text; or phase 5 finding an agent that, given its own router table as a target and a criticism of it, does not change its next use of it (that would show text in context is not enough for "operative return", and the model would need to say what more is).

**M10. This repository's conventions already instantiate part of the workflow, by hand.** The log is a history with precedence (Part IX); results files are evidence leaves; the owner's decisions are declared contracts and obligations (Part III: "A **declared** contract is stipulated by the modeller"; "\(O_p\) is the set of obligations being addressed or protected"); a job tagged *fixed* is a protected obligation ("protected obligations \(P\), fixed for the comparison", Part XI), which is the row the HV word list lacked (H69's unmapped notion 2); a frozen plan is an assessment at a fixed index ("An assessment is an event with a frozen contract", Part 0); the rule that a changed question is a new claim is the historical index (Part VIII); "every patch records what it gives up" is "(P) does not rank alternatives. Losses outside \(P\) must be exposed" (Part XI). *Would count against it:* a judge finding a convention that contradicts the passage it is mapped to, or a passage that the convention reads wider than written (the fault the H69 check found twice in the skill's word list).

**What the model does not claim.** That any agent belongs to the theory's classes: "It does not prove that any human, machine, institution, or lineage belongs to the classes defined. It defines the classes." (Part 0). That an agent is creative, understands, or knows: those are (G), Deploy and (EK), each of which needs a construction witness and an owned history, and phase 1 does not attribute them. The model says what would have to be shown, and phases 3 and 5 test the parts that can be tested at the grain of text.

## 5. Predictions, as counts that could fail

Numbered by phase. Each names the count that would falsify it. Where a count belongs to a phase's own plan (the number of documents, arms and repeats), this file fixes the form and the phase plan fixes the number before that phase runs; the falsifier's shape is fixed here and is not changed there.

**Phase 1 (the model).**
- **P1.1.** The model's word list has one row per term it uses; every row quotes file 10 or is marked as a construction with the passage that permits it. The judges find **zero** rows that contradict file 10 and **zero** unmarked constructions. Any one falsifies it, and the row is reworded before the model is frozen; three or more falsify the claim that this sketch was written close to the theory, and the model is rebuilt from the theory rather than patched.
- **P1.2.** Each of Q1 to Q6 receives a statement in the model's terms whose falsifier is a run this repository can make. **At least five of six.** Fewer falsifies it, and the phase 1 results file names which unknowns the theory, as written, cannot reach.
- **P1.3.** Of the eleven notions of file 10 that the HV word list uses without a row (H69), the model's word list carries a row for **at least six** and names the rest as not needed by the model, with the reason. Fewer than six and the model is narrower than the skill it is meant to place.
- **P1.4.** The judges, marking the model part by part with the eight marks, leave **no part idle** and **at most two parts loose** after their own search for holders. Three or more loose parts and the model is loose as a whole; it is not frozen until each is held or cut.

**Phase 2 (the reading).**
- **P2.1.** The coverage map, fixed before reading, gives every part M2 to M10 **at least one** piece of evidence in hand that bears on it. A part with none is named as unreached, and phase 3's plan must reach it or the results file says the programme cannot.

- **P2.3.** The owner's material on the harness of Q1, when supplied, is sorted by M8's distinction (what the harness set: inputs or outputs). If it sets only inputs and still shows the loss, M8 is falsified as written.

**Phase 3 (the first run).** Arms, on documents no run in the record has read, fetched by manifest: **(a)** one Claude Code agent (Sonnet 5) carrying its own history through every step of the skill's procedure on a document; **(b)** fresh calls, one per step, each handed the whole transcript so far; **(c)** fresh calls, one per step, each handed a summary of the transcript written by a fixed program; **(d)** the partition harness: fresh calls, one per test of Step 5, each handed only the document, the frozen question and the one test, and a final call handed the pile of answers to write the report. Same skill (file 33), same documents, same framing. Three repeats per box. Marked by field (plan 52's fields, RAN or not per test, the eight marks per part, the same-explanation verdicts, the pulling pairs, rivals built), first marker and a blind second marker, agreement read by field (Planning file 2). Every tool call audited.

- **P3.2 (from M5 ii).** Arm (c) shows fewer same-explanation verdicts, fewer pulling pairs and fewer rivals than arm (a), on **more documents than not**; and its part-by-part marks agree with arm (a) as arm (a) agrees with itself (the P3.1 measure). Falsified either way: no drop on the cross-step fields, or a drop on the part-by-part fields.
- **P3.3 (from M8).** Arm (d) shows fewer same-explanation verdicts and fewer pulling pairs than arm (a) on **more documents than not**, and its part-by-part marks agree with arm (a) as in P3.1. Falsified if arm (d) matches arm (a) on the cross-step fields.
- **P3.4 (from M6).** In **zero** runs does a reader name a rival or a pulling pair whose target was not in its context and not in any file its tool audit shows it read. One falsifies M6 as written.
- **P3.5.** No reader reports a test as impossible to run (the record's CANNOT count has been zero in 147 plus 48 runs); the phase plan predicts the count again and it is not this file's to fix.

**Phase 4 (the skill map).**
- **P4.1.** Every operation in the theory's dependence order (section 6's table) is assigned to exactly one holder or to "no home". **At most three** operations change holder between the section 6 sketch and the frozen map after phases 1 to 3. Four or more and the sketch was drawn by habit, which is the fault section 3 warns of; the results file says which findings moved which.
- **P4.2.** At least **one** operation the sketch gives to a skill is shown by phase 3 to need state or a harness (per M5 or M8) and is moved out of the skill into the workflow's arrangement. Zero and the model made no difference to the map, which would mean phases 1 to 3 did no work for Q6.

## 7. What counts as each outcome, decided before reading

- **A row of the model's word list holds** when file 10's quoted sentence says what the row says in the theory's terms, read no wider than written. It is **loose** when the row would survive a rewording that named a nearer passage. It is **a construction** when the theory permits the object (as Derivation 5 permits a contract to be an organization) but does not contain it, and it is marked so. It **contradicts** when file 10 says otherwise in a sentence the judge quotes.
- **A part of the model is marked** with the eight marks of HV file 33, by a judge, with the holder quoted (a sentence of file 10, a result in the record, or a prediction of section 5 that could fail). *Held if* and *unknown* follow file 33's readings.
- **A field agrees between two runs** when the marker's record for the field is the same (RAN or not; the same mark; the same count of verdicts, pairs, rivals) on the same document. Agreement is a count of documents, by field, never summed across fields or arms.
- **A reading in phase 2 contradicts a part** when a recorded result, quoted, is something the part says will not happen, or the absence of something the part says will. A result the part merely does not mention is not a contradiction and is not counted as support.
- **The owner's word** is the sentence the owner writes, recorded in Decisions here as written.

## 8. What follows either way

- **P1.1 to P1.4 hold:** the model is frozen as this project's first authority file, with its word list, and phase 2's plan is written.
- **P1.1 or P1.4 fail:** the model is reworded or rebuilt before freezing; a second judging round runs only on the changed parts, five judges at most; the results file records what the first round forced.
- **P1.2 fails:** the unknowns the theory cannot reach are named in RELATIONS as questions for the Semantics project (read only there; the ask is written here), and the programme goes on with the ones it can.
- **P2.2 finds contradictions:** each is a forced change to the model, made as one new numbered file answering all of them (Planning `changes.md`), before phase 3.
- **P3.1 fails:** M5 (i) is wrong as written: a transcript is not enough to carry the state, and the model must say what a stateful agent carries that its transcript does not. That is a finding about the physical module reaching the grain of text, and it goes to the front of phase 4.
- **P3.2 or P3.3 fail in the direction "no drop":** M5 (ii) or M8 is wrong as written, and the owner's harness observation (Q1) is not explained by component deletion; phase 4 then cannot use M8 to place attention, and says so.
- **P3.2 or P3.3 fail in the direction "part-by-part marks drop too":** the fields were wrongly sorted into within-step and cross-step; the sorting is redone from the reports, as a new claim, and the run is repeated under the new sorting before anything else follows.
- **P3.4 fails:** M6 is wrong as written, and the model must say where the target came from (the reader's own weights, which is M2's territory: fitted, and unconstrained off its history).
- **P4.1 or P4.2 fail:** the sketch in section 6 was drawn by habit or the model did no work; the map is redrawn from the phase 3 results with the sketch struck through, kept as the record of what was expected.

## 9. What would count as failure of the programme itself

- A phase 1 model whose every part is a frame (declared) and none a claim: the theory forbids resting on it, and the programme would be describing, not explaining.
- No prediction of section 5 that phase 3 could falsify surviving the judges: then this is "a plan that cannot fail" (Planning file 2), and it is not frozen.
- Phase 3 unable to separate any two arms on any field, with within-arm agreement also low: the marking, not the model, is at fault, and the programme returns to the marking plan before any reading of the model.
- A judge showing that the programme's use of file 10 rests on one of the theory's own attack points (Part 0, A to E) as if it were settled. The model must not assume sufficiency (A) or that any agent belongs to a class (Part 0's "does not prove").

## 10. Known weaknesses, stated before use

- **The writer of the model is an agent of the kind the model is about,** and so are the judges and the readers. The theory allows a system to be wrong about its own capacities ("Systems can be wrong about their transports, their observations, their criticisms, and their own capacities", Part I); nothing here removes that, and the arms of phase 3 are the only check that does not pass through an agent's own report of itself.
- **The grain is text.** \(\operatorname{Org}_\ell\) of a transformer is outside the programme by choice (section 1). A claim at that grain could contradict this model without the model noticing; the programme says nothing there.
- **The owner's harness observation is claimed, not in the record.** Phase 2 asks for the material; until it comes, M8's answer to Q1 rests on the theory alone.
- **Three per box is small** (Planning file 2: "0 of 6 is compatible with a fault that fires one time in ten"). Phase 3's counts are read as counts.
- **Two of the five judges' tasks on this draft read the same record the draft was written from.** The judge that builds the rival plan and the one that reads file 10 against the model are the two that can find what the writer could not.

## 11. What this plan does not test

- Anything at the grain of weights or activations.
- Whether any agent understands, is creative, or creates knowledge in the theory's senses (Deploy, (G), (EK)). The model names what would have to be shown; no phase here shows it.
- The skill's own faults. HV file 33 is frozen; a reader's failure under it in phase 3 is read as evidence about the arm, not the skill, unless the same failure appears in every arm, in which case it is held for the HV project and written in RELATIONS.
- The semantics itself. Where the model finds file 10 cannot reach one of the owner's unknowns, that is recorded as an ask, never as a change; the theory's audit is the Semantics project's.
- The other model (the one that audits the semantics). It is not used in this programme; if a phase wants it, that phase's plan says so and the Semantics project's rules for handing it things apply.

## 13. Traps

- **Reading M1 to M10 as the model.** They are the sketch the judges cut. The model is phase 1's file.
- **Counting the six unknowns answered as a score.** One unknown the theory cannot reach matters more than five it can.
- **Letting phase 2 count as a test.** It reads the fitted evidence; the first test is phase 3.
- **Reading a reader's report as what the reader instantiates.** Derivation 9 forbids it; only what changes between arms is evidence.
- **Naming the readers' failures under the skill as the skill's.** File 33 is frozen; section 11 says when a failure is held for HV.
- **Writing the word list rows wider than file 10 writes them.** The H69 check found that fault twice; every row quotes.
- **Assuming a harness cannot work because one did not.** Part XIII: a finite list of failures is not a barrier proof.
- **Moving a phase's count into this file after the fact.** Counts belong to the phase plans; this file fixes the shapes of the falsifiers and is not edited after it is frozen.
