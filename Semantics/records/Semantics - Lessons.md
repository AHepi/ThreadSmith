*The Semantics project's own record, kept here from 21 September 2026 (decision S1), in the same four files as the shared record (now kept in `Language/records/`). Only cases where something failed while being made or tested, and how it was fixed.

26. Both clauses Claude wrote for round 4 had faults that Claude's own checks missed and the other model found: one conflated "loose" with "fitted"; the other stated its passing condition on the outcome alone, which the thing it was meant to exclude also met. Fix: revised clauses for round 5, and a line in the skill: run any test you write on the thing it is meant to catch and on its nearest innocent neighbour.
27. The first draft of prompt 30 contained one negative word in an instruction ("when they cannot"). Caught by the program that searches each prompt for negative wording. Fix: reworded as "when either one is missing".
35. The judgement-phrase pass written into file 30 could be passed by any phrase at all: it asked for one change showing "met" and one showing "unmet", and far-apart changes are always available. Shown on first use: zero marks in 32 rows, and both phrases already known to rest on judgement passed. Fix: each pair is held against a near case (file 41).
49. File 41 asked the other model to build a tighter pair for any row the near case left open, and gave one example of the form (water present, beside tank at least half full). For O4 it built a pair that adds a controller to the index display, which distinguishes a controller from a passive display and leaves the disputed question, whether a measured regularity is an explanation of production, where it was; the model saw this itself and withdrew its first mark. The theory already holds the distinction that places O4: a production question's contract holds interventions on the upstream part, an identification question's contract holds edits to the observed value, and the two are different questions. File 41 did not point the model at that passage, so it invented a mechanism instead of using the theory's own. Fix: file 55 quotes the distinction in plain words, asks the model to find and quote the passage in its copy, and to build the pair from it, marked separately (PLACED BY THE THEORY'S OWN DISTINCTION) so a row placed that way is never counted as one the pass placed.
50. File 55 told the other model that if a faithful table fails none of the four conditions, "that is a finding against the theory's stated claim, and belongs at the top of the report". That sentence was written from the attack list in Part 0 alone ("lookup tables ... all fail one of the four"). Part V, further on in the same document, already says that a table genuinely encoding an organization's response to every admitted change "is not a table in that sense and is not excluded". The model found the qualification, said so, and still put the finding at the top, because the instruction said to. The finding is about one front-matter sentence, and the instruction inflated it. Fix: file 57 asks for the finding restated at its size beside both sentences; the rule is that before an instruction names a claim of the theory as a target, the whole document is searched for that claim's own qualifications, which is now possible because file 10 is in the repository (log 56).
S1. The script that updated the navigation files stopped on one line whose text had changed, and the commit and push that followed it in the same command went ahead anyway, so a commit reached main with the root README changed and the Semantics README, INDEX, LEGEND and the rest untouched. The chain joined the git steps with "and" but the script ran as a separate statement, so its failure stopped nothing. Fix: the edits were finished in the next commit; the rule is that a script whose success the commit depends on runs first, in the same chain, so that its failure stops the commit.

S2. The two-stage instructions carried the round's expected answer in the part the agent reads: S72's named O24 and O48 as the rows to find, S76's carried the frozen prediction and the pack carried S75 and the earlier audit's sampling sequence; the audit instruction printed Stage 1's verdict before the auditor's own reading; and S75 attributed to the instruction a SAME rule the tested agent had written after the data. Found by the five-reader review (S78), each item checked against the files. The rule: a prediction is frozen in the record and kept out of the tested agent's pack; a second reader writes its reading before it opens the first reader's; the rule that decides a mark is written into the instruction before the run, and a rule adopted after the data is recorded as adopted then.
S3. At the start of the 23 September session Claude read the wrong project: asked to continue "where this branch left off", it took the newest commits (the Language project's) as the branch's work, reported Language's agenda and launched a Language premise checker before the owner said "Semantics not language". Fix: the checker was stopped before it wrote anything. Rule: when a repository holds several projects, name the project and its last log entry back to the owner before starting work.
S4. Asked which "next language testing stage" was meant, the owner picked the Language option and then sent "Whoops", "No", "Yes I did", "No no I meant semantics" in quick succession. Claude acted on each message as it arrived: it started work in the Language folder twice and recorded a decision there. Undoing the first start, a `git revert` whose output was not read failed, and the `git commit --amend` chained after it rewrote the Language commit itself under a "Revert" message. Fix: a soft reset onto the remote (which held the right commit), then two plain revert commits; the Language folder ended byte for byte as it was. Rules: when the owner's messages contradict each other within a minute, wait for them to settle before acting outside this folder; never chain an amend after a command whose result has not been read.
S5. S80 and S81 were numbered from this project's own entries (S79, then S80); LEGEND's rule gives the shared sequence's next number, which stood at L86, so S87 and S88. Found by the S81 builder after S80 was running. Fix: names kept, the deviation recorded in log S80. Rule: read the highest number across all three projects' logs before naming a new entry.
S6. The first S80 design compared the skill (13,648 words and an instruction to use it) with a one-line system prompt, and its task named two of the skill's own target kinds to every reader; both would have made the result unreadable. Caught by the outside cross-examination (Atria and Mimo, both RUN WITH CHANGES), not by Claude's checks. Fix: a length-matched placebo method under the same framing, and a neutral task. Rule: a treatment that is a long text is compared with a text of the same length, and the task names nothing the treatment supplies.
S7. S80's probes and pilot used tiny prompts, or one provider with thinking off. At the real size (a 33,000-token system prompt, thinking at high effort) Mimo spent its whole 64,000-token budget on reasoning and wrote no report, on every skill and placebo run (six of six failed after three attempts each). Fix: the runs were paused; Mimo is to be rerun with a larger budget. Rule: pilot each provider at the full prompt size and full effort before a counted run.
S8. A probe of the second S80 version hung for eleven minutes: a stream stayed open without going silent long enough for the idle timeout to fire. Fix (the builder's): a total deadline on every stream as well as the idle timeout. Rule: every network call has a deadline on the whole call, not only on silence.
S9. The S81 contamination check voided all six Sonnet returns. Two causes: the harness's own report hand-back tool was counted as a tool outside the folder, and the word "prediction", listed as a leak word, is an ordinary word in the theory and the case book, which every honest reader paraphrases. The synthetic test had used made-up transcripts and words, so neither showed up. Fix: the hand-back tool exempted, and each hit read and cleared by Claude with the reason in the receipt; the first judgements kept under new names. Rule: test a contamination rule on the real texts and a real transcript before the run, and choose leak words that do not occur in the material the reader is given.
S10. Two S80 runners shared the providers without a shared limit: the reader run held three Mimo slots while the S81 audit needed them, and the per-provider limit of three (decision S12) holds only within one process. Fix: the S80 run was paused (it resumes where it stopped) before S81's calls began. Rule: one runner per provider at a time, or a lock shared across processes.
