## Reader

## The question, frozen
Does the two-stage pattern — one fresh agent reads the theory bare against all 52 cases with an identifier on every verdict, a second fresh agent checks that return row by row against the sources and builds the fix card and draft list from what survives, and Claude reads both and determines — find what is wrong with Claude Fable Semantics? Over the range of rounds it is meant to run (S72 against file 10, S76 against file 11, and rounds after), and over the range of theories it is meant to handle (a formal semantics of roughly eight to ten thousand words, revised between rounds, tested against a fixed case set that grows by a handful each round). Three things are asked, and I answer all three: whether each part does inside the run what the instruction says it does and the S72 returns show it; whether the pattern can fail a wrong theory and pass a right one, with a route by which a wrong theory is reported wrong rather than absorbed by a reading, a PARKED file or a held-back list; and whether each part is held in place by a job, so that swapping a part for its nearest neighbour breaks something. This is a \"does it achieve its purpose?\" question about a method, not a question about whether the theory is true.

## Overall
**Verdict:** makes sense with repairs

The split does a real job and did it. Remove the second stage and the S72 round ships a draft list with two changed verdicts instead of one and a case card placed on the wrong pair; the audit caught both, and a fix card that runs its restatement on the case that forced it, on two cases it must leave alone, and on a self-written attack is the best piece of work in either return. So the pattern passes the first test: it can move a result, and the movement was recorded. Where it is loose is around the split, not in it. The rule that decides SAME from CHANGED on all fifty-two rows was written by the agent being graded, after the data, and the determination adopted it as the instruction's own terms, which it is not; forty-four rows carry the same boilerplate sentence. The bin named "Explicit already; every case agreed" tests only that two readings agree, and one of its twelve lines is demonstrably not explicit in file 10 — file 11 has just added it. The audit's reach is set by the labels of the return it audits, and from S76 the sampling rule and the expected answer both sit inside the tested agent's own pack, so the next round as packed runs backward from the result. Thirty-three unchecked rows become that round's baseline and agreement with them is its pass condition. None of this makes the O48 finding wrong — it is internal to file 10, it was reached again by an outside judge from the text alone, and I checked its quotation by hand — but the round was saved by that case existing, not by the pattern's design. The repairs are small and mostly editorial: put the reading rules in the instruction, take the answer out of the pack, and let the determiner pick the sample after the return arrives.

## What would make it harder to vary

- Run Stage 1 twice, by two fresh agents, on the same pack, and print the rows where the two tables differ. The method currently has no measure of how much of a verdict is the theory and how much is the reader, and it is the cheapest job to add because the pattern already spawns fresh agents. If two independent testers disagree on ten of fifty-two rows, the table is mostly measuring the reader and every count in S75 changes meaning. If they disagree on none, the audit's nineteen-for-nineteen agreement stops being ambiguous and starts being evidence.
- Fix the reading rules in the instruction instead of letting the graded agent supply them. Write the SAME/CHANGED test in two columns (does the case's verdict change; does the passage's claim change), rename "Explicit already; every case agreed" to "Bare and amended agree on this case", and bar clause identifiers from the warrant column of any line claiming the authority already says something. Each of these three is one sentence in the instruction and each one closes a route by which a real change is absorbed by a name.
- Strip the answer out of the tested agent's pack: drop S75 and the S72 Stage 2 return from the S76-1 pack, move the prediction below build.py's owner-section marker, and have Claude choose the audit's residual sample after the Stage 1 return arrives. The prediction stays frozen and written down; it is simply held by the adjudicator instead of handed to the instrument, which is the whole difference between a pre-registration and a target.
