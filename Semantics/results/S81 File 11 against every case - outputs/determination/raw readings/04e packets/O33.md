### O33
FINDINGS: The colleague's table has a column per knob, but every row moves both knobs together and no row moves one alone, so the contract excludes the single-knob edits — the very changes under which the active commitments could matter to the question. Such a contract does not satisfy non-circular dependence and is therefore not a contract on which an account can be claimed. Under that contract neither knob is an input at all, since a port is an input only when the admitted edits contain one that sets it directly. If the exclusion of single-knob edits is not stated with a scope, non-vacuity's scope requirement fails as well.
QUOTE: "A contract consisting only of relabelings, or excluding every change under which the active commitments could matter to \(\mathcal Q\), does not satisfy non-circular dependence and is therefore not a contract on which an account can be claimed." (Part V - Non-vacuity)
QUOTE: "The contract \(C\) is a declared subset of the physically admitted edits, and every physically admitted edit excluded from \(C\) is excluded by a stated scope, not silently." (Part V - Non-vacuity)
QUOTE: "A port \(v\) is an **input** under \(A\) when \(A\) contains an edit that sets \(v\) directly." (Part II - Roles are derived)
