## 0. What is being asked

The owner (S60): "Of the of machines that could do rudimentary math, what needed to be removed in order for them to stop doing that math. Ignore the fact that they were evolved to solve a problem, I want to know what that evolved information actually is, given the environment it was instantiated in."

So two answers, both exact: (1) for each of the nine sums (Avida's logic tasks NOT, NAND, AND, ORN, OR, ANDN, NOR, XOR, EQU), in each program that does it, **which instructions** had to be removed for the sum to stop, and what those instructions have in common across programs; (2) **what those instructions are** when Avida's simulated computer runs them: set evolution and reward aside, and describe the thing as it stands, relative to what runs it (Avida's instruction set and processor, its input and output channel, the numbers it hands in).

Log S111 left two things open that this must close: its removal test took out, at once, every site whose *single* removal stopped a sum, and still about a fifth of the NOT-doers went on doing NOT (so single removals miss something); and it counted instructions ("19 to 26 for EQU") without saying what they do.

## 1. The programs

- **All living genotypes** in the final populations (update 50,000) of the nine S111 runs (three copy error rates, three seeds): 23,332 genotypes holding all 32,193 living organisms (read from `detail-50000.spop`). This is wider than S111's "covered" set (the most common genotypes up to 90% of the organisms): every organism is covered, 100%.
- Each genotype is run alone in Avida's test processor on Avida's fixed inputs (the three numbers `0x0f13149f`, `0x3308e53e`, `0x556241eb`, built so that every combination of bits occurs; `source/main/cEnvironment.cc` 1284-1288). A genotype **does a sum** if the test processor reports it (the same measure as S111).
- For each sum: the number of genotypes doing it, the number of organisms they hold, and their share of all organisms and of the organisms Avida's world counted as doing it. Every count below is given both per genotype and weighted by the number of living organisms of the genotype.

## 2. What had to be removed

- **Removing** an instruction means replacing it by `nop-X`, the instruction that does nothing and is not read as a label (as in S111), added as a 27th instruction in the analysis runs only.
- **Stopping a sum** means: after the removal the program still makes an exact copy of itself in the test processor, and no longer does the sum. A removal that stops the copying stops every sum in the test processor too (a program that never splits is credited with nothing); those removals are counted separately, as "the copying part", and are not what is asked for here. Whether the output of the sum is still *written* when the copying is broken is checked from traces for the nine most common genotypes (section 3).
- **A minimal removal set** for a program and a sum: a set of sites whose removal stops the sum, while no smaller part of it does.
- **The search**:
  1. every single site of every genotype (exhaustive: about 2.3 million programs run);
  2. every **pair** of sites of every genotype, among the sites whose single removal leaves the program copying (exhaustive to size 2; about 75 million programs run, about 1.5 hours on 3 processors by the timing run). A pair counts as minimal for a sum if neither of its sites stops the sum alone;
  3. for each program and sum with no removal set of size 1 or 2: an **irreducible-set search**. Start from the set of all sites in the trace's routes for that sum (section 3: every output the sum's check accepts, and the instructions that made it), restricted to the sites whose single removal leaves copying; if removing that set stops the sum, put sites back one at a time, in 5 random orders, keeping each one back if the sum stays stopped; each order ends in a set from which no single site can be put back. If the start set does not stop the sum, start instead from all sites whose single removal leaves copying; if that does not stop it with copying left, the pair is recorded as "not stopped by the search";
  4. for the nine most common genotypes (one per run): every **triple** of such sites as well, to see how many minimal sets of size 3 the irreducible-set search misses.
- **Limits, stated now**: the search is exhaustive only up to pairs (triples in the nine most common genotypes); sets of 3 or more found by step 3 cannot lose any one site, but they are not all the minimal sets and not necessarily the smallest. Removal by `nop-X` is one kind of removal; deleting the site (which shifts every later position) is not tested.
- **Reported, per sum**: the share of doers (by genotype and by organism) whose smallest removal set has size 1, 2, 3 or more, or none was found; the minimal sets' instructions, in genome order, with each site's **role** read from the trace (section 3): the output write, an input read, a gate (the operation that combines numbers), a mover (swap, push, pop, stack switch), a register choice (the `nop` read after an instruction, which picks the register it acts on), a control instruction (jumps, heads, conditions), or none of these. What the sets share across programs: the roles and instruction kinds, and their order. Worked examples with the actual instructions and positions.

## 3. What it is: read from Avida's trace

- **Trace**: Avida's own `TRACE` command in analysis mode (`source/analyze/cAnalyze.cc` 1725), for every genotype, on the fixed inputs. For every executed step it prints the instruction and its position, the three registers, both stacks, the heads, the inputs read, the last output written, and the sums credited so far (`cOrganism::PrintStatus`, `cHardwareCPU::PrintStatus`).
- **Replay of the trace** (not a simulator: it only follows traces Avida wrote, and is checked against them at every step). For each executed instruction, which registers and stack places it reads and writes, as read from Avida's source (`source/cpu/cHardwareCPU.cc`: `Inst_Nand`, `Inst_TaskIO`, `Inst_Swap`, `Inst_Push`, `Inst_Pop`, `Inst_Add`, `Inst_Sub` and the rest; register choice by the next `nop`, `FindModifiedRegister`; stacks as in `cCPUStack.h`). The replay carries, for every register and stack place, **where its value came from**: an input read (which of the three numbers, by which IO at which site), a constant (the start value 0, a length or position written by `h-alloc`, `h-search`, `get-head`), or an operation (which instruction at which site, on which values). At every step the value the replay carries must equal the value in the trace; every step where it does not is counted and reported as left over.
- **Routes**: each output written by IO, with the three most recent inputs, is put to Avida's check for the sums (`source/main/cTaskLib.cc` 369-448, the "logic id" rule: each of the 32 bit places of the output must be the same function of the same bit places of the inputs; that function is the logic id, and each sum accepts a stated list of ids, 513-575). The first accepted output for each sum must be the one at which the trace's own count for that sum goes from 0 to 1; any disagreement is reported. Every accepted output for a sum is a **route** for that sum; the one Avida credits is the first.
- **The circuit** of a route: from the output back to the input reads, through the operations; the movers and register choices are wires, not parts of the circuit. The nodes are the operations the instruction set has (`nand`, and any `add`, `sub`, `inc`, `dec`, `shift-l`, `shift-r` on the way); the leaves are the three input numbers and constants. Constant parts are folded to their value, named ZERO, ONES (all 32 bits set) or OTHER.
- **Canonical form**: identical sub-circuits merged; the operands of `nand` and `add` put in a fixed order; the three inputs renamed by the order that gives the smallest written form, so that two programs running the same circuit on different inputs are counted together (the exact form, with the inputs named, is kept too). Reported per sum: the number of distinct circuits (canonical forms) over all programs and runs, how many programs and organisms run each, its number of gates, how many **different instruction strings** realise it (the route's sites in genome order, as letters, and separately the whole genomes), and whether the smallest circuit possible with `nand` alone is among them (NOT 1 gate, NAND 1, AND 2, ORN 2, OR 3, ANDN 3, NOR 4, XOR 4, EQU 5).
- Check: each canonical circuit, computed on the three inputs, must give an output Avida's check accepts for the sum.
- **One fully worked example per sum**: the actual instructions from the input reads to the output write, with positions, registers and values, in the instruction set's own terms and in plain logic.
- **Removal against route**: whether each minimal removal set cuts every route of the sum (contains at least one site of each route's instructions, register choices or controls), and whether redundancy (a sum still done after a single removal) goes with the program having more than one route.

## 4. What it depends on in the environment

Each test runs the same genomes (all genotypes that do some sum; letters unchanged) in Avida's test processor with **one thing of the environment changed**, and, where the circuits allow it, the outcome is predicted from the circuits **before** the run and compared after it.

- **E1. The meaning of the logic instruction.** The letter `u` given the meaning `nor` instead of `nand` (one line of the instruction-set file), and then `and`. Prediction from the circuits: with every `nand` gate replaced by `nor`, each circuit computes the dual function (NOT stays NOT; NAND becomes NOR, AND becomes OR, ORN becomes ANDN, XOR becomes EQU, and back), so each program's sums should move to their duals; with `and`, each circuit's changed output is computed and put to the check. Every output of the trace is recomputed this way, so a sum may also appear from another route. Programs whose control depends on the values the gate makes may not follow the prediction; the count of those is reported.
- **E2. The input and output channel.** The letter `y` (IO) given the meaning `nop-X`: prediction, no sum at all (every route begins and ends at IO), while copying continues wherever IO plays no part in it.
- **E3. The numbers handed in.** Three other triples of input numbers (random 32-bit numbers, fixed seed, given with Avida's `RECALCULATE` manual inputs), and the same three fixed numbers in another order. Prediction: a circuit made of `nand` gates on inputs alone gives the same sum for any inputs; circuits with arithmetic or constants may not. Compared per program.
- **E4. The whole instruction set.** The same letters read with the 26 meanings assigned to the letters in another order (three random shufflings): prediction, no copying and no sums.

## 5. What would count against each conclusion

- **Against (1), "what had to be removed is the route's instructions"**: removal sets that do not cut the routes the trace shows (the sum stops for another reason), or routes whose instructions can be removed without stopping the sum when the program has only one route; many program-sum pairs with no removal set found.
- **Against (2), "what it is, is a circuit of the instruction set's gates"**: many trace steps where the replay's values differ from the trace; a first accepted output that is not where Avida's count changes; circuits that, computed, do not give the sum; as many distinct circuits as programs (no sharing), which would make "the same circuit in different strings" empty.
- **Against (3), "it is a circuit only relative to this environment"**: sums unchanged when the gate's meaning changes (E1) or when IO is removed (E2); sums of `nand`-only circuits changing with the inputs (E3); sums surviving a shuffled instruction set (E4).
