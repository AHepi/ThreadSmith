## Tools: what GLM may do, decided by test

**Decision: (b).** Each call runs in a **sandbox**: a fresh folder in the scratchpad per attempt (`<scratchpad>/s105_sandboxes/<tag>.a<N>`), holding only copies of the manifest's files (each checked by md5 at the copy) and the brief as `BRIEF.md`. Before sending, the helper refuses if any file there is a link, holds the key, or holds anything shaped like a key; after the attempt it compares every file with what it copied and records whether the sandbox came back unchanged. HOME, the Claude Code config folder and TMPDIR of the call are a fresh folder `<scratchpad>/s105_homes/<tag>.a<N>`, outside the sandbox, never `~/.claude`. GLM may **Read, Glob and Grep inside the sandbox**, and may run **only `python3 -m model.run …`** from it. Two locks, each tested on its own:

1. **Claude Code's own flags**: `--restricted` (file tools confined to the working folder; user, project and local settings ignored), `--tools Read,Glob,Grep,Bash`, `--allowedTools "Read,Glob,Grep,Bash(python3 -m model.run:*)"`, `--permission-mode dontAsk`, `--permission-prompts none` (anything not allowed is refused, nobody is asked), `--settings {"includeGitInstructions":false}`, `--strict-mcp-config`, `--disable-slash-commands`, `--no-session-persistence`, empty system prompt. `CLAUDE_CODE_SIMPLE` is not set: in simple mode Claude Code 2.1.283 offers no Glob or Grep. The first request of such a call, captured at a stand-in, holds the empty system prompt the CLI always sends ("You are a Claude agent, built on Anthropic's Claude Agent SDK."), an environment block (the sandbox path, platform, date), the brief, and the four tools; `includeGitInstructions` false removes a git-attribution reminder the CLI otherwise adds.
2. **A guard on every command**: Claude Code's `CLAUDE_CODE_SHELL_PREFIX` is `tools/glm_sandbox_shell_guard.py` [md5 a0b625a934f169690a32752c478e7ad9]. Every command the Bash tool would run is handed to it as the whole shell line. It never starts a shell: it runs a command only if it is, character for character, `python3 -m model.run` with `--claim FCnn` (repeatable), `--scale N` (at most 4), `--time-cap N` (at most 60), `--brief` or `--help`, from the sandbox; then it runs Python directly with `--no-write`, `-B`, and a clean environment that does not hold the key. Everything else is refused with one fixed line and logged. The guard closes two gaps the flags alone leave: Claude Code lets read-only commands run inside the working folder (`cat`, `ls`, `grep`, `head`, `wc`, `file`, `echo`, `pwd`, `date`, `whoami`, `history`, `git log`) and `ps -ef` (other processes' command lines, not their environments); and a shell glob inside the allowed command was expanded (`python3 -m model.run --claim ../../../s105_decoy/*` ran, and would print file names outside the sandbox in its error).

The two locks above keep every route to the environment closed instead: Claude Code refused every such command, and the guard never passes the environment on.

## How the replies will be read

1. **Nothing is opened until all four calls end.** No reply, receipt, reasoning file, attempt file, stream file or guard log of this round is opened until every job has ended its last allowed pass (a reply accepted, or failed with no pass left): the run log holds `s105_glm_loop: every pass ended; …` and `loop ended <UTC time>`, and the process in the pid file has exited. The progress lines of the log (start, sent, still running, accepted, not accepted, done) may be watched; they hold no reply text. If a call is still running 24 hours after the launch, the orchestrator may stop the runner by its PID and record the calls not ended as not returned; all four have then ended.
2. **What counts as a reply.** A reply counts only when `<tag>.response.txt` is in the returns folder: the helper writes it last, and only for a reply whose last non-blank line carries END OF REPORT. A failed call counts neither for nor against any finding. Connection failures, timeouts, HTTP 429 and 5xx are not answers from the model (lessons S21, S24): the helper tries again; a job failed only on the connection after pass 3 may be sent again only under a new note written before sending. A job failed after pass 3 on answers the model gave (no END OF REPORT) is final, and its job is recorded as **not done by that call**. After a container restart the runner is looked at and relaunched from a shell started after the restart. A receipt that shows the key found in the output (`key_found_in_output_and_replaced` above 0), or a sandbox not unchanged, is reported to the orchestrator before anything else is read.
3. **A reply is a set of arguments to rule on, not a result.** Nothing in the maths, the program or the text is kept, changed or dropped on a reader's say-so. Silence is not agreement: a definition no job attacks is not thereby shown to hold, and a claim that held on every model tried holds on nothing beyond them. A model a reply marks "not run" is run by the checker before it is ruled on.
4. **Tabulation first.** Once all four calls have ended, **one fresh Opus 5.5 agent**, which built nothing of this round and has read no reply, tabulates the four replies before any ruling: for each finding, its job and id, the items and lines, what fails, the model or computation and whether it was run, the proposal whole, its form (maths, code, or which of the three text changes), and the inventions it rests on. It flags each proposal that adds prose (not taken, S40) and each that would reverse or weaken an owner's answer (not taken, S41). It writes `results/S105 Round 3 - tabulation of the replies, before any ruling.md`, created at once and filled as it goes (lesson S28), and rules on nothing.
5. **Three checkers, by area of the text.** At most three fresh Opus 5.5 agents (decision S40; lesson S38), one per area, as in round 2: area 1, L1–L228 (Parts 0 to IV); area 2, L229–L372 (Parts V to VIII); area 3, L373–L632 (Parts IX to XVI). A finding goes to the area holding most of the lines it bears on; a finding on the maths alone goes to the area of the lines its definition or claim formalizes. The sizes of the three groups are counted before any checker starts (lesson S36). Each checker, for each finding of its area:
   1. says in one line whether it holds: against the maths, against the words, against an invention only, or not;
   2. where it holds, writes the fix as maths, the changed or new definition or claim beside the old one;
   3. puts the fix into its own copy of the program and runs the claims it touches, under each open reading and from computed inputs, not hand-set tags (lesson S39);
   4. changes the text only by deleting a span, replacing a span by its formal statement, or replacing a span by a pointer; it never adds prose.

   Each writes `results/S105 Round 3 - area <n> - verdicts and formal fixes.md` with its model copy, its runs and its text changes as JSON, created at once and filled as it goes. At most five Claude agents run at a time (decision S17).
6. **Inventions.** A fix may write an invention into the text only when its ruling says, in so many words, that the text should now settle it, names it, and gives the formal statement; every such change is listed as "settles Inn". A counterexample resting only on inventions the text leaves open changes nothing in the text by itself. A choice no register entry records, found by a reader or a checker, is recorded as an invention, numbered after the last I number in use; that record is not a move (S36).
7. **Integration.** One fresh Opus 5.5 agent merges the three model copies into one, numbers the new inventions, runs every claim, writes the formal core and the formal claims after round 3 as new files beside the old ones (never over them), and applies the permitted text changes by program to a new copy, `tests/105 The semantics, standing alone, after round 3.md`; the text under review and every earlier text are never written over, and nothing is written into `authority/`. Each applied change is compared by program with its fix, byte for byte, and the words outside formulas are counted before and after. It lists every pair of fixes that bear on one another.
8. **One critical review.** Then one critical review by Fable 5.1 (decision S35) reads the whole against this rule and the owner's words, reruns the program where it doubts a result, and writes `results/S105 Round 3 - critical review of the round.md`. Nothing is final before it.
9. **The orchestrator decides contested points.** Where the review contests something, the orchestrator (Claude) decides, with its reasons why this and not the other, under decision S13; it keeps the fix, or sends the contested points, all together, to **at most one** fresh second checker, which rules between the fix, the review's proposal and a third fix of its own, in maths and code. Either way it is recorded.
10. **Arguments, not numbers.** Four jobs saying the same thing decides nothing; neither do the length or the confidence of a reply.
11. **The owner's answers (S41).** No line is held. A proposal that would reverse or weaken an answer is not applied. A finding that the maths or the text does not say what an answer says, or says more, is ruled like any other finding, and its fix must say what the answer says.
12. **Parked points and owner questions, as before.** A proposal about what hard to vary covers is recorded as parked and not applied (S33, S34). A proposal that would move where values are placed is a question for the owner and is not applied. A new question goes to the owner only where the owner's words leave it open and neither the texts nor a computation settles it (lesson S40); it is written with both sides, each with an everyday example, and the line it concerns is held until the owner answers.
13. **The owner's words bind every fix**: no list, count, grade, ranking or record doing the explanation's work (S20); nothing about what must happen to candidates (S21); no word S23 forbids in any statement, name or gloss, "argument" as reasons why this and not that, every accepting tentative (S23); physical possibility only where information or knowledge is instantiated or transformed, and as content (S25 to S27); nothing settled, and a ruling out by a claim taken as given a choice (S28); nothing about what hard to vary covers (S33, S34); every invention recorded (S36); no new prose (S40); the four answers (S41).
14. **No new prose in the text.** The text changes only by the three kinds of change above. The program that applies them refuses any other, and the count of words outside formulas is reported before and after.
15. **Quotations are compared.** Each quotation a reply or a ruling relies on is compared with the text under review or the maths; where it is not found, that is recorded and the point is ruled on what the text says.
16. **Moves, counted strictly**, as round 2's second checker counted them (lesson S41): the formal changes that answer a finding that holds (a changed or new definition, a changed claim or encoding, a change to the program's reading of a definition), plus the text changes applied. Not counted, and listed as not counted: register entries (inventions recorded, including those a fix settles); re-based claims, whose statement follows a counted change with the result unchanged; new test claims and test parts; records of parked points and owner questions.
17. **A round with 0 moves ends the series**: "no moves left" (S35). Otherwise the next round goes to the new copy, under its own rule, written and committed before sending.
