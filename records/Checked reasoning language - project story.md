## The goal
(The Language project's goal, where the record began. The Semantics project's is in `Semantics/ORIGIN.md`; the HV Skill's in `HV Skill/ORIGIN.md`.)

Find or design a formal language that everyday reasoning prose can be turned into, that an external checker can read and find faults in (contradictions, jumps in reasoning, mismatches of category, property or type, and anything else that aids reasoning), and whose findings can be turned back into plain prose. The external checker is the one essential thing.

## How the pieces fit
Example first: you write four sentences about tomato plants. A translator turns them into twelve ledger lines. A checker finds a contradiction, a jump and a kind mistake. A read-back turns those findings into a plain report that points at your sentences.

| Part | What it does | What it hands on |
| --- | --- | --- |
| You | Write prose | Prose, to the translator |
| Translator (a language model) | Turns prose into ledger lines. The only step that guesses | Ledger to the checker; what does not fit to the leftover bin |
| Ledger | Holds your text as lines, each tied to your sentence and marked said / filled in / usual case | Lines, to the checker |
| Checker (fixed rules) | Finds faults. Never guesses | Findings, written in the ledger language |
| Read-back (fixed rules) | Turns lines into plain prose. Never guesses | The report, to you |
| Leftover bin | Holds prose that could not be written as lines | A "not checked" list, into the report |

As actually built (log 07), the checker has three layers. s(CASP) does the reasoning. The driver (a small program) decides what to ask, takes lines out to see what changes, and writes the report from fixed wording. The checker rules are the fixed rules s(CASP) uses for every ledger. The translator, for now, is Claude working by hand.

## The twelve properties (short form)
A. What gets written down: 1 one name, one thing; 2 kinds; 3 strength marks; 4 separate parts with a direction; 5 the question, frozen.
B. What keeps the checker external: 6 fixed meaning, always an answer; 7 a sameness test; 8 evidence, not a score.
C. What keeps it tied to your words: 9 two-way anchor; 10 source marks; 11 leftover bin; 12 exact read-back.

## Word list
- Prose: what you write in everyday language.
- Translator: the language model that turns prose into a ledger.
- Ledger, line: your text in the formal language; one line per thing you committed yourself to.
- Checker: a program with fixed rules that reads a ledger.
- Finding: what the checker returns (lines in contradiction, a missing line, a part that does no work, a counter-case).
- Read-back, report: fixed rules that turn lines into prose; the findings after read-back.
- Leftover bin: prose that could not be written as lines; not checked, always listed.
- Contradiction / jump / kind mistake: lines that cannot all hold / a conclusion nothing said makes follow / a thing treated as the wrong kind of thing.
- Source mark / strength mark / anchor: who put the line there / how general it is / which sentence it came from.
- Job: one particular thing the language has to get done.
- Held / held if / two routes / loose / idle / borrowed / fixed / unknown: the eight marks for how firmly a part is held in place.
- Seen / claimed / worked out / recalled: how I know a thing about a tool. Seen: watched it happen. Claimed: a source I opened says so. Worked out: follows from tagged things. Recalled: memory only.
- Bridging limit: how big a gap the checker may fill by itself before calling it a jump.
- Filling in: the translator adding a line you did not write.
- Driver: the small program that puts questions to s(CASP), takes lines out to see what changes, and writes the report.
- Checker rules: the fixed rules s(CASP) uses for every ledger.
- Rig: the driver and the checker rules together.
- Frozen / patched: the rig as it stood after paragraph A / the copy with logged changes.
- Patch: any change to the rig after it was frozen.
- MAKES / SHOWS: a line that says what produces a thing / a line that says how we can tell.
- Departure from the usual: one of your sentences goes against a usual-case line, and nothing says why.
- Likeness: a claim that two events are alike.
- Tendency: what a thing does if left alone.
- Influence; presses; holds: whatever acts on a thing, pressing toward a change or holding it against its tendency.
- Slot: one of the five fixed places every causal line fills.
- MAKES / LETS / STOPS / DESPITE: the basic causal words, each defined by how the slots are filled.
- Law: a general rule about pressing, kept in the checker, the same for every ledger.
- Word-recipe: an ordinary verb spelled out in the small pieces. Chain: happenings in order.
- Response class: a kind given by how the thing answers a press (fixed; heavy and standing; light and loose; held; doer).
- Combinatorial: a few pieces that combine into endlessly many meanings, as words do.
- Shape / name: the broad causal pattern a verb shares with many others (the checker sees this) / the particular label that sets it apart (the checker does not).
- BECAUSE / SINCE: what produced it / a reason to expect or believe it. Different tests run on each.
- Standing: whether a line is the point of its sentence (CLAIMED), taken for granted along the way (GIVEN), or only supposed for a what-if (SUPPOSED).
- Legal line: a line the rulebook (file 20) allows. Legal does not mean checked.
- Sameness test: lists what two ledgers both say, what only one says, and whether the same fact has a different standing.
- Shape book: the shared list saying which shape each verb has. Verbs not in it are reported as "not checked".
- Rig 1 / rig 2: the first checker set-up, for arguments (file 10) / the second, for causes written as pressing patterns (file 17). Not yet joined.
- Joining table: a small fixed table saying what overall pattern two patterns give when one follows the other.
- What-if test: asking whether the result would still have happened with the cause taken away.
- Pair (audit workflow): two changes to a situation a person can picture, one showing a phrase is met and one showing it is unmet.
- Near case: a case sitting close to the line between the two changes of a pair, so the pair has real work to do in placing it.
- Gauge: the list of phrases marked BORROWED: JUDGEMENT. It shows how much of the theory still rests on judgement.
- Passage (DeepSeek test): the wording of a case sent to a reader under test, with nothing in it about the contest.
- Answer key: what a reply is marked against. For invented cases, the planted fault. For real contested theories, the weak point the critics name.
- Setup: what a reader is given along with a case. The DeepSeek test has four, each adding one thing to the one before.
- Control: a case whose explanation is sound, there to catch a reader that criticises everything.

## How to work on this project
- To read: start with this file, then the newest numbered file in the log. For what the system can and cannot say today, read file 18, not the theory pages.
- To change a project file: check Decisions first; make the change as a new numbered file; never overwrite an old numbered file.
- To write a ledger: follow the rulebook (file 20). If something will not fit, put it in the bin with the reason, and log it as a candidate new kind of line.
- To change the checker: never edit the frozen copy. For every patch, record what it gives up as well as what it fixes (see the list above the next step). Change the patched copy, log the patch here with the paragraph that forced it and the layer it changed, then rerun every ledger.
- Before any test or research: freeze the predictions as their own numbered file first.
- Before any build: merge the theory into one page and freeze it. The build tests that page only.
- After a clean sweep: add cases chosen to break the rig, run them against the frozen copy, label them as added after the plan.
- To edit the documentation: add a log entry here, update Status, add to Decisions or Lessons if one applies. The log is added to, never rewritten.
