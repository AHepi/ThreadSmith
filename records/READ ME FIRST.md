# Checked reasoning language - the current set

Twenty files. Everything here is live. Superseded versions were left out, and each one is named below so nothing goes missing quietly.

## Read in this order
1. **Checked reasoning language - project story.md** - the whole record: goal, where things stand, how the pieces fit, word list, the numbered log, next step.
2. **38 The ledger language - complete definition.md** - the language itself, clean, with no history in it.
3. **39 Prompt - translate a text into the ledger language.md** - hand this to a translator together with file 38.
4. **Checked reasoning language - Status.md** - the short summary.

## What each file is for
- **project story / Decisions / Lessons / Status** - the record. Decisions holds your own words. Lessons holds only things that failed while being built or tested. Status is the summary.
- **38 The ledger language** - the definition. Supersedes every earlier rulebook.
- **39 Prompt** - the translator's task, order of work and output form, in positive wording.
- **38 Checker rigs - both, current.zip** - the working checkers, the bridge that joins them, every ledger, and the full log of questions and answers.
- **37 Test plan / 37 Test results** - the blind sample from the other model's literary corpus: eight outside texts, seven matched its answer keys.
- **35 Test plan** - what was expected of the third pile of changes, frozen before building.
- **30 Skill - hard-to-vary** - the reasoning skill, modular, with its router and map.
- **30 / 28 / 27 Next instruction for the other model** - the audit prompts. 30 is the live one: it updates the other model's workflow and runs a fresh round. 28 and 27 are the two rounds already run, kept because their cases are referred to by name.
- **24 Workflow / 24 Owner's guide** - what to hand the other model for auditing the theory, and how to run it.
- **22 / 21 Test plan and Test results** - the Mondays paragraph and the Markus paragraph, each with its predictions frozen first.

## Left out on purpose
- Rulebooks 20, 23, 33 and 34: all superseded by file 38.
- The ledger language, file 36: superseded by file 38.
- Checker rig bundles 07, 10, 17, 21, 22, 34 and 36: superseded by the current rig bundle, which was rebuilt for this set so that it includes the last two fixes.
- Skills 05, 08, 10, 11, 14, 17, 21, 22 and 29: superseded by skill 30.
- Instruction 29 to the other model: never run, and its content sits inside instruction 30.
- Theory pages 01, 11, 15 and research pages 04, 12, and their plans 03, 06, 09, 12, 16: the work they record is summarised in the project story's log, and the language they argued for is now file 38.

## Traps
- **Taking the rig bundle as matching an older test write-up.** It holds the checkers as they are now. The write-ups say what the checkers said on the day.
- **Handing file 38 to a translator on its own.** It defines the language; file 39 gives the task.
- **Handing the hard-to-vary skill to the other model.** Its wording is full of "never" and "may not". File 24 is the version written for that model.
- **Reading a test result as a pass mark.** Every one of them names what it did not test.
