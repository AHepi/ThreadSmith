# HV Skill - Lessons

*The HV Skill project's own record, kept here from 21 September 2026, in the same four files as the shared record (now in `Language/records/`, complete to log 59). The entries copied from the shared record keep their numbers. New entries here carry the letter H and one more than the highest number this log has used, H55 first; new decisions and lessons are numbered H1 onward. See READ ME FIRST in this folder.*

Only cases where something failed while being made or tested, and how it was fixed.

4. The improved skill's description ran 28 characters over the length limit and failed the validator. Fix: trimmed two trigger phrases; validator passed.
6. The skill said "look at what a tool does, not what it says", and I could not: desk research only reaches what makers say. Fix: added the tag "claimed" so this shows in every write-up.
36. Compiling the corpus was begun through the research add-ons, which ask the owner for permission each time; the permissions did not arrive and one add-on was out of searches for the month. Two calls were spent before this showed. Fix: compiled from Claude's own knowledge, with "not looked up in this chat" stated in the file and a source check named as a step before the run.
38. Plan 42's "change that should leave the marks as they are" renamed people and places, which works for invented cases and not for real theories: string theory with the strings called something else is still string theory. Found while building the rig for the corpus. Fix: rewording, the same claims in other words, for three cases, with a note in file 47 that rewording is a larger change and can move a mark for its own reasons.
39. The record disagreed with itself: log 43 and the next-step line said the answer keys were unchecked, while file 43 carried the corrections from a source check made the same day. The log entry was written before the check and never brought forward. Fix: noted in log 47 and the file taken as the record of the check.
40. Thirty reader agents were launched in one go, before the owner had seen the plan, and the owner had to stop them by hand. The plan was frozen and the design was sound on its own terms, and none of that was the point: the owner works by verifying each step before it starts. Fix: the owner's rule (decision 38), start only after verification, and phases in plan 49 that each wait on the owner's word.
41. Plan 42's design carried over to the Claude-reader test without asking whether the owner wanted a Claude reader at all. The owner did not. Fix: plan 49 was written to the owner's terms before any rig was touched.
42. Ten of the forty-nine planned sources could not be fetched, and the reasons were not the ones expected: two canonical papers exist online only as scans with no text in them (Bell 1964, the Prusiner lecture), two pages load their words by script so a fetch returns the furniture and none of the text (Wolfram's chapter, The Fable of the Keys), and three publishers refuse an automated fetch outright. A reachability probe that reads only the response code says "200" for all of these. Fix: the probe now counts the words that come out, not the code, and every substitution is recorded in file 50 with its reason.
43. Trimming by marker is where a corpus quietly goes wrong. Six files kept a page of site navigation, three kept a table of contents in place of the chapter, and one stopped after 1,383 words because an early heading read "References". None of it shows in a word count alone. Fix: the opening of every file was read back and the trim rules corrected until each began at the document's own first sentence.
44. The pilot crashed on its first call because the skill folder sat in the previous test's directory and the runner looked for it in its own. Three runs had already gone out, so the run was part spent before the fault showed. Fix: the skill is now copied into the run folder and checked against file 30 by difference before any call, and the runner skips a run whose file already exists, so the three were kept.
45. Two of 147 replies came back empty: the service returned the reader's thinking cut mid-sentence and no report, with no error code, so the runner saved them as complete. A run that "succeeds" with an empty reply looks like a run until someone counts the words. Fix: the shape check now flags any reply under 300 words; the two were kept as first attempts and run once more, recorded as a rig patch that gives up nothing.
46. The marker checked each claim by searching the source and reading the first hit. Ten claims were marked invented or outside the text that way, and all ten were in the text: one hyphenated across a line ("il- lustrative", "feed-back"), one garbled by extraction (a formula), the rest simply later hits than the first ("sticks of lead", "64%", "19% ... 5%", "18 different combinations", "21-member", "90% response range", "a posteriori"). Found when a bare-reader report quoted a detail already marked invented in another. Fix: the check prints every hit, and a claim is marked absent only after all of them are read.
47. In conversation mode one reader wrote its whole report in its sixth turn before being told the conversation was over, and all twelve asked three to five questions a turn against the skill's "one part and one change at a time". Neither was caught by the rig, which counts turns and not questions. Fix: recorded in file 54; a question count per turn is now printed by the shape check.
48. The numbering clashed a third time, and this time the rule from Lesson 37 had been followed: the chat started from the current zip (file 44). The set on main had moved on to 45 and 46 while the chat worked, so the chat's 45 to 52 met the repository's 45 and 46 on import. Fix: renumbered 47 to 54 (decisions 37 to 43) by a script that rewrote every reference inside the files; the map is in this entry. The cause is two chats appending to one numbered sequence from different starting points; the rule now is to check main's last number before the first new file, not only at the start.
