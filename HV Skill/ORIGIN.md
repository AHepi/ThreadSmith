# Origin

**The idea.** "A good explanation is hard to vary: you cannot change its parts and still have it explain what it is meant to explain. A bad explanation is easy to vary: its details could be swapped for others and it would 'explain' just as well, which shows the details were never held in place by the thing being explained." David Deutsch, *The Beginning of Infinity*. Quoted from [SKILL.md](<authority/hard-to-vary/SKILL.md>).

**Its relation to the semantics.** The skill's front matter: "This skill sharpens it using a formal theory supplied by the user, 'Claude Fable Semantics'. That theory's terms are mapped to plain words in `references/word-list.md`." The skill is a way of criticising, not a truth-meter: passing does not prove an explanation true, failing does not prove it false.

**How it entered the project.** The skill existed before the language work began. Decision 2: "Actually first, use the hard to vary skill to come up with a theory about the properties a candidate language would need." Log 01 used it to arrive at twelve properties; log 02 made the first improvement from what that taught, and Decision 8 set the pattern: "if you've spotted a way to improve the hard to vary from the process you just engaged in, make the improvements, then test it against the research and the compiling stage."

**The earliest version in the record** is the one used at log 01; it is not in the bundles and no number is given for it. The earliest numbered skill file is 05. The current file is 30. See [INDEX.md](INDEX.md) for each step between.
