# HV Skill - relations to the other projects

A hypothesis ledger of this project's connections to the other projects in the repository. Each entry is a claim, its current status in the record's own terms, where the evidence is, and what is still open. A claim lives in the project that makes it; entries are added, updated or marked rejected, never removed. Numbers R1 to R5 were given when the ledger was one file at the root; they are kept.

Status words used: **stated** (written in a file as a claim, not tested), **seen** (watched to happen in a recorded run), **open** (a question the record itself raises).

## R6. The boundary between this skill and the planning work
**Claim.** The skill is a judge, not a chooser. Given one explanation and one frozen question, it returns marks on parts, breaks, gaps, what would tighten the explanation most, and one next step offered as a candidate; it never decides what is done about any of that. Everything that chooses belongs to the planning work: which claim to put under test and in which order; which of the skill's tests to run on which sources, how many times, and when to stop; what is predicted and frozen before a run; what counts as a test forcing a change; how a corpus is split and what is held out; how readers and markers are arranged and audited; what a result licenses; and the protocol of the owner's word. The shared conventions at the repository root are the minimum of that discipline every project follows; the planning work, when it has a project, holds the fuller method, and this project's tests follow it.
**Where the line runs through the skill as it stands.** Three places sit on the seam and are decided one way each. (1) The report's "One next step" stays in the skill as an offer to whoever plans, never as a decision. (2) "What would make it harder to vary" stays in the skill: it is about this explanation. (3) The module `references/testing-against-cases.md` (how to run a home-made test: freeze cases first, keep a nothing case, keep first outputs, log every patch, tick predictions) is planning content on loan inside the skill since log 08; it stays in file 31 because a change to the skill needs a test, and it is named here as the first thing that crosses when the planning work has a home. The front matter's trigger "to test one against cases found in research" is the same loan. Building an explanation from nothing (`building.md`) is neither judging nor choosing and stays where it is; it is a seam to a third kind of work, generation, which no project holds.
**Current status.** Stated, by decision H5. Seen in this session's own record: every step from H55 to H64 that chose what to run, how often, and when a change was forced was planning done inside this project's log because no other home existed; the skill's own outputs (marks, breaks, candidates) were never the thing that decided.
**Evidence.** `authority/31/hard-to-vary/SKILL.md` ("This skill is a way of criticising, not a truth-meter"; the report's seven headings, ending in "One next step"); `references/testing-against-cases.md`; `RESEARCH-CONVENTIONS.md` at the root; plans H56, H58, H63 and results H57, H59, H62, H64 as the planning record.
**Open question.** Whether the planning work is a fourth project with its own letter and record, and whether the shared conventions stay as they are once it exists. Both are the owner's.
