**(1) The parts claimed to do the work**

- A. Writing the test first makes you say *what* before *how*, so nothing is written unthought.
- B. It forces small steps, one behaviour per test.
- C. It makes the code testable, and testable means loosely coupled.
- D. It leaves a suite that catches every regression.
- E. The evidence: teams that switched saw defects fall forty to ninety percent; drop the order and defects return.

**(2) What holds each in place, or what could stand in for it**

- A. Loose: a written spec, a type signature or a five-minute design note before coding also says what before how; nothing here says the test must be the vehicle.
- B. Loose: any habit of small commits gives small steps, and a test written straight *after* each behaviour covers one behaviour just as well.
- C. Held if the tests are isolated unit tests; tests-first written at the integration level force no decoupling, and tests written after, with the same coverage target, force the same testability.
- D. Loose on the order: a suite written after the code catches the same regressions. "Every regression" is a catch-all with no gauge; nothing says what a missed regression would look like.
- E. Unknown: "teams that switched" chose to switch, and switching brings coaching, attention and fresh care all at once. Flip it: had defects not fallen, we would hear "they did it wrong". "Remove the order and defects come back" is asserted, not shown.

**(3) The weakest part**

The *order* itself. Every part except A survives if the same tests are written seconds after the code, so the explanation may be about having a thorough suite, not about writing it first. One change that would show it: one team, one codebase, half the features done test-first, half done code-then-test with the same coverage rule, same reviewers, same period. Count escaped defects and measure coupling in both halves. If the gap vanishes, the order does no work and the suite does; if it stays, A is doing something the suite alone cannot.

**(4) Verdict**

RELY ON IT FOR A NARROWER QUESTION: why teams with a thorough, isolated automated suite ship fewer defects. The suite is held. The claim that the test-first *order* produces cleaner design, and the size of the fall, are not yet held by anything in the explanation.
