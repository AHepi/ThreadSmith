# 22 Test plan - your Mondays paragraph

Written before the run. Not edited afterwards.
Authority document: "Claude Fable Semantics - standalone theory" (file 10). Translated by the rulebook (file 20), using SINCE from log 21.

## What kind of case this is
One long chain: each "so", "therefore", "since", "which means" hands a conclusion on as the next step's reason. Nothing so far had more than two steps. Patch 6 (SINCE, and naming the conclusion) was fitted to the two-step Markus paragraph, so this is its first hard case.

## How I will translate it
- Each "A is B" sentence becomes a general line. Each "so / therefore / since" becomes a SINCE pointing from a conclusion back to the step before.
- "once Monday disappears" is SUPPOSED, not claimed.
- "forced to absorb", "causing Tuesday to become Monday": a line that MAKES.
- Rule 2 (one name, one thing) will force me to split some words, because the paragraph uses them in two senses. I expect at least: "command" (having the right to be obeyed / issuing an order) and "Monday" (the day / the order it gives). Every split is my decision and will be listed.
- "must", "obligated", "can", "optional": the language has no way to say these. They become plain descriptions, and that goes in the bin.
- "unemployed time": a figure of speech. I will write it as the writer uses it, as a plain description, and say so.

## What I expect from rig 1, unchanged
| Step | I expect |
| --- | --- |
| Monday lacks authority, since it is a beginning | To be expected. The three lines before it do give it |
| We have no duty to obey, since it lacks authority | To be expected |
| Monday is a suggestion | No connection. Nobody says the command goes unheeded, and the command is not the day |
| It ceases to exist if ignored, since it is optional | No connection |
| Tuesday becomes Monday | A CONTRADICTION: the step supposes Monday is gone and then produces a Monday |
| The week collapses into one day | No connection |
| Time becomes unemployed | No connection |
| We save civilization | No connection. "Civilization" and "save" appear in no earlier line |

And two things I expect the unchanged rig to get wrong, because patch 6 was fitted to a two-step argument:
- it will name EVERY conclusion as "the point of the paragraph", not only the last;
- it will judge each step alone, and will not say that a later step rests on an earlier one that already failed.

## What would count as a failure
The rig flags either of the first two steps; or misses the contradiction; or names only the final conclusion without being patched.

## What the checker cannot see, whatever I do
The shifts in meaning. It will see them only as the splits I was forced to make.
