# Language - Lessons

Only cases where something failed while being made or tested on the Language project, and how it was fixed. Lessons 1 to 50 are in the shared Lessons file beside this one; 51 to 53 are copied from it. New lessons here are numbered L1 onward.

51. Plan 45's predictions for N17 (a LETS line against a stated tendency) and N22 (SO THAT answering "cannot tell") were written from the audit report's one-line descriptions of those cases, not from the case texts. N17-A says "assisted", which is HELPS, and states no tendency; N22-A supplies both the dependency and the change, so the plan check can fire. Found by the other model before any run. Fix: a forcing case's prediction quotes the text it will be run on; the plan stays as written and the discrepancies stand beside it.
52. The rig bundle holds no program for the sameness test, though plan 45 names it as a thing to run; logs 19 and 20 ran it by hand. Found when the other model looked for its command. Fix: write it down as a program before Part A, named as new, and log what it compares.
53. The two drivers call s(CASP) at a fixed path on the machine the rigs were built on. On any other machine the first query dies with "no such file", the driver exits 1, and the raw log is empty, which can pass for a run that found nothing. Found in the other model's execution attempt, which read the empty log correctly. Fix: a link at that path, or one changed line; the trap is now in Language/README.
L1. Two chats wrote the one shared record in the same hour and both took entry number 57; the second push to main was rejected and the entry had to be rebuilt as 58. Then it happened again the same day at 58, caught only because the second chat pulled before writing. Fix: this folder's own record, with L-numbered entries that cannot collide (decision L1).
L2. The rig-1 driver asks every ledger the same questions (BECAUSE claims, plans, likenesses, exemptions, denials), and when a ledger has no lines of a kind s(CASP) answers with "predicate does not exist". The driver counts that as "no such claims" and prints NO FAULT FOUND, so the report cannot tell a question answered from a question it could not ask; 640 of the 2,085 sections in the historical raw log are such answers. Found by the worker, which refused to read those reports as clean and read the raw logs instead. Fix: the report should list the kinds of claim the ledger had none of; until then, read the raw log beside any NO FAULT FOUND.
L3. L63 turned an owner's aside, "quite unlike the semantics audit where meaning preservation is prioritised", into a given job saying the opposite of what the owner meant, and carried it into the pairs that pull and into the lead-in of decision L5. Found by the owner within the hour. Fix: a job marked "given" quotes the owner's words beside it; a paraphrase is marked as Claude's until the owner has read it; L64 corrects the file, and the lead-in of L5 is cut back to the owner's words.
L4. The consequences program's first run listed a stated fact, "the balcony plants are tomato plants", as derived: its parser for clause heads let a head run across a line break and swallow the line before it. Found by reading the ten "derived" facts against the thirteen lines before writing anything. Fix: heads may not cross a full stop or a line break; the first run kept beside the second; and any new program's first output is checked against one fact known by hand before it is believed.
L5. An agent with write access to the repository, handed a bundle whose brief said "you change nothing in any record folder", wrote a status reconciliation into the record and pushed it instead of doing the work, and reported that it had "pushed results". A rule stated in the middle of a brief does not hold against a task the agent can see in front of it. Fix: the brief's first paragraph says the only output is one zip and forbids the repository outright; better still, the worker has no repository access at all.
L6. Plan L71 described ledger C as fault-free from a memory of one phrase in log 07 ("C right with no change"), which meant the opposite: the checker was right to find the henhouse contradiction. The plan was frozen and run before the premise was checked, so the test lost its fault-free half. Same family as Lesson 51 (predictions from descriptions, not from the thing itself). Fix: before a plan names an earlier result, print that result again with one command and quote the report's first line in the plan.
L7. The consequences program (L65) was written on a ledger with no told or supposed lines, and calls the driver's query function without the driver's list of lines outside the world being looked at. On any ledger with a told world it pools the world with the actual ledger and derives contradictions the checker rightly refuses. Found by Astra Ultra reading the program (L73), confirmed here. Fix: a tool that reuses the driver must set every switch the driver's own check sets, and its first run on a ledger of each kind (plain, what-if, told) is checked before it is believed.
L8. The sameness program's near score counts shared words and ignores NOT, so a line and its negation scored as near (L73, T07-D). Fix: a NOT on one side only breaks a near pair and is printed as opposite.
L9. Plan L66's E2 named Emerson's consistency passage as the one unplanted passage expected to raise a false alarm; the key, which the same hand had sealed an hour before, marks that passage planted. The prediction was written from a picture of the corpus, not from the key. Fix: a prediction that names a passage is checked against the key's table before the plan is frozen, by reading the table, not by memory (the same rule as Lessons 51 and L6, now three times).
L10. The forced finding 3 of L75 ("the driver prints the sentence only in what-if and plan headings; one line fixes it") was written from the shape of the L66 reports, not from the driver. Four reviewers read the code (L76): `describe_lines` prints the sentence beside every line it lists, in eleven branches; the untraced findings are JUMP and NO CONNECTION, which list no lines, and the heads of BECAUSE, SINCE and PLAN findings; the traced sentence numbers were the translator's, echoed from the ledger's `whose` field. Built as written, the fix would have changed nothing the reader failed on. Same failure as 51, L6 and L9, the fourth time, now about code. Fix, structural this time (review A4): every plan and every proposed repair carries a premise block in which each premise is a quotation from a named file with its path and SHA-256; a premise that cannot be quoted is written as a guess; and a second agent checks the premises before the plan is frozen. Occasions covered: every plan and every repair proposal from L77 on; each names this lesson and says where its premises are quoted.
L11. Two tools were overwritten in place this week against the project's own rule: `tools/install_scasp.sh` (commit 37e33da, the smoke lines replaced) and `tools/consequences.py` (commit 20bb00f, the Lesson L4 parser fix), neither with a give-up line; and `tests/L60 Handoff` was overwritten under an exception the conventions do not contain (review A5). The overwritten versions are recoverable from git only. Fix: a tool is a numbered file; a new version is a new file beside the old with a give-up line; a file corrected before it reached anyone carries a note in the file saying so. Occasions covered: every file in tools/ and tests/ from now.

## Traps
- Letting a lesson drift from the log entry that records the failure. The log is the record; a lesson points at it.
