# Splits: fitting, held-out, reserve

**Fitting.** Every source a change to the thing under test was written from, or checked on after the change. Once a source has served that way it stays fitting for every later version.
**Held-out.** Sources no marker has read beyond their shape. A version is judged on them once; when read and marked, they become fitting for the next version. So the set shrinks with every version and needs a supply: a manifest and a fetcher that can bring more, with every substitution recorded and its reason.
**Reserve.** Corpora with an answer key the reader never sees: a passage beside what critics name as its weak point, or a sound explanation with one planted fault that maps to one test. They are judged against the key, not by a marker's reading, so each test of the thing under test gets its own hit and false-alarm counts.

Freeze the split as a numbered file before the run that uses it. Never let the first marker read a held-out report.
