# Changes: when a result forces one, and when to freeze

A change to the thing under test is a new numbered file, made only after a test forces it. A fault seen once forces a repeat under the unchanged version, not a change. What the repeat's outcome forces is written into the plan before it runs (under plan H56 any one recurrence forced both changes file 54 had proposed, including one whose own break did not recur). The same runs are then made again under the new file, with the recurrence criteria unchanged and new lines added for any fault the change could itself cause.

Where several open faults share a cause, one change answers them all in the fewest passages; the diff between the two versions is the record of it. A proposed change is checked against the thing under test before it is made: a line that is already there is not a change.

Freeze: when the hardening plan's predictions hold, the version is frozen and its front door says so; no further change until the next aim asks. Change candidates that remain are held in the ledger, not applied.

Where these came from: HV Skill README rules; file 54's held changes; H57 (a break recurred, file 31 forced); H59; H62 and H64 (candidates held); plan H67 (one change for every open fault; the freeze).
