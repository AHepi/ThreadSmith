# Freezing: plans and predictions

A plan is written before its run and not edited after the first run goes out. It holds, in this order: the question; what is fixed (the authority under test checked by difference, the readers, the settings, the sources and how they are rebuilt, the framing word for word); the runs (which, how many, in what order, where the outputs go, what is done with an empty return); what counts as each outcome, decided before reading, in words a stranger could apply; the predictions, each a count that could fail; what follows either way; what would count as failure of the test itself, so that a clean run can still be read as saying nothing; the plan's own known weaknesses, stated before use; what the plan does not test; traps.

Rules used so far: three repeats per box is better than one and still small, and does not separate a wording fault from a run ("0 of 6" is compatible with a fault that fires one time in ten); a borderline case is quoted and not counted; arms (readers, versions, transports) are never added together; an addendum records a change of transport before the first run and names what it gives up; an observation made while writing the plan (a proposed change that turns out to be misaimed) is written into the plan so it cannot be made after.

Where these came from: HV Skill plans H56, H58, H61, H63, H67; root conventions.
